## §3 구조 개선 설계 — Phase L0~L5

> 번호는 기존 ARCH 로드맵(Phase 0~4)과 구분 위해 L 접두. 통합 우선순위는 §5.
> 각 Phase는 "검증 게이트 통과 = 완료" 기준. 헤드리스는 현재 922/922 + deploy-gated(P630/P632) 상태이므로 신규 게이트는 그 위에 얹는다.

### Phase L0 — 파이프라인 소생 (P0, 1세션)
- **L0-1 워커 계약 복구**: ① 배포된 워커가 리포 `cloudflare-worker-proxy.js`와 일치하는지 확인(`curl -X POST https://aio-proxy.zmfhd007.workers.dev/anthropic` 405 재현 → 리포 코드에 POST 핸들러 있으면 **재배포가 곧 수리**). ② 재발 방지: `scripts/ci-runtime-contract-check.mjs`(기존 파일) 확장 — 라이브 워커에 OPTIONS/POST 스모크, 계약 불일치 시 CI fail. ③ 클라 쪽 405 수신 시 U5의 빈 패널 대신 명시적 에러 카드.
- **L0-2 번역 폴백 헤드라인 보존**: aio-data.js `localEnrichSingle` 경로에서 `ko_title` 부재 시 **원문 제목 그대로 표시**(템플릿 제목 생성 금지) + 템플릿 본문·해석 중복 1회로 축소. 게이트: "[번역 대기]" 카드에 실제 헤드라인 존재를 검증하는 헤드리스 테스트 1건 추가.
- **L0-3 SW 동기화**: 라이브에서 v52.4 잔존 원인 조사(sw.js `skipWaiting`/`clients.claim` 체인, 등록 URL 캐시버스터). 버전 불일치 감지 시(이미 감지 코드 존재) 사용자 노출 새로고침 유도 배너로 승격. 게이트: 배포 후 실브라우저에서 `[AIO:sw]` mismatch 경고 0건.

### Phase L1 — Verdict Gate: 데이터 상태→어조 매핑 (구조 핵심, 1~2세션)
- **설계**: 판정문을 만드는 모든 지점이 공용 헬퍼 `renderVerdict(state, verdictFn)`를 통과하도록. `state ∈ {live, snapshot, fallback, truth-blocked}`:
  - live → 단정 판정 허용 / snapshot → "MM-DD 기준" 접두 강제 / **fallback·truth-blocked → 판정문 생성 금지**, "라이브 미수신 — 판정 보류" + 원데이터 출처 링크.
- **1차 적용 대상(이번 실측 사고 지점)**: VIX 기간구조(C3), VKOSPI 해석(C4), kr-supply 요약, 수급 폴백 카드, 백워데이션/사이클 판정문.
- 게이트: "truth-blocked 상태에서 단정 판정문 렌더 0건" 헤드리스 테스트 (R280 계열 기계 게이트로 RULES 승격 — R3에 따라 신규 R번호 부여).

### Phase L2 — TruthGate 급변 예외 + KR 세션 캘린더 (1세션)
- **L2-1 동행 급변 통과 규칙**: cross-source 두 소스가 **같은 방향으로 임계 초과 변동**이면 차단하지 않고 통과(진짜 폭락은 모든 소스가 동의한다 — 이번 실측: Naver -8.03/Yahoo -8.45 동방향). 차단은 방향 불일치·단독 소스 급변에 한정. 차단 시 PUBLIC STATUS에 심볼·사유 노출(현재는 콘솔에만).
- **L2-2 KR 기준일 SSOT**: KRX 휴장 캘린더를 미국 캘린더에서 분리. KOSPI/KOSDAQ 전일종가는 **Naver `compareToPreviousClosePrice`/직전 실거래일 종가 필드를 직접 사용**(자체 파생 계산 금지). "종가/장중" 라벨은 `marketStatus` 필드에서 유도. 게이트: kr-home·kr-supply·실측 3자 등락률 편차 ±0.05%p 이내 테스트.
- **L2-3** fetchKrDynamicData 그림자 정리(ARCH Phase 0-2 그대로 흡수) — orphan 5건 소생/폐기 결정이 L2-2의 전제.

### Phase L3 — 점수 SSOT + 커버리지 게이트 (1~2세션)
- **L3-1 산출 확정 규칙**: breadth/종합점수는 시세 수신 커버리지 임계(제안 90%) 도달 전 **미확정 상태** — UI는 "산출 중 n/m 수신"을 표시하고 이전 확정값을 유지(플래핑 금지). ARCH Phase 0-1(R280 기계 게이트)과 동일 계열이므로 **하나의 작업으로 통합**.
- **L3-2 판정 소스 단일화**: 종합점수·국면·진입가능 여부를 단일 스토어에 두고 홈 히어로/상단 칩/티커 진입적합성(L4)/테마 칩(U7)이 전부 구독. 티커의 '시장' 항목은 기술 건강도(74)가 아닌 종합 판정을 참조.
- **L3-3 분해 재현성 강제**: "점수 구성 상세" 표시값의 가중합 == 표시 종합점수를 헤드리스 테스트로 강제(감점 항 있으면 행으로 표시). **매크로 온도계(완전 재현 실증)를 표준 패턴으로 문서화.**

### Phase L4 — 자가진단→운영 루프 (1세션 + 상시)
- **L4-1** `getAutoOpsReadiness` 결과를 ① PUBLIC STATUS 패널 항목 ② CI artifact(JSON)로 승격. warn 목록(특히 `_fieldTs` 초과 9종 F4, 만료 콘텐츠 6건)이 `/data-refresh`의 작업 큐가 되도록 스킬 입력 형식 정렬.
- **L4-2 사망 차트 킬스위치**: 차트 공용 렌더 경로에서 마지막 datapoint 나이 > 지표별 임계 시 자동 "MM-DD 정지됨" 오버레이 + 판정문 억제(L1 연동). 1차 대상: 건강점수 추이(F3), 심리 바차트(F2), VIX 기간구조(C3).
- **L4-3** X3 대응: readiness 스캔을 idle 콜백/워커화 또는 캐시(스캔 결과 TTL)로 — 45s 프리즈 제거.
- **L4-4** F6: "오늘 시장 핵심" 헤더를 실데이터 날짜 기반으로 ("최근 시장 핵심 (7/5)" 등).

### Phase L5 — 실효성 보강 + 표시 정리 (1~2세션, 협의 후)
- **L5-1 아시아 세션 리스크 입력**: ES/NQ 선물 + KR 지수(이미 수신 중)를 종합 판단의 입력 축으로 추가할지 **운영자 결정 필요** (미국 중심 설계는 의도일 수 있음 — 단, 최소한 홈에 "선물/아시아 세션" 타일 1개는 P1 권장). 브리핑 24h 윈도우(08:00 마감)의 장중 속보 레인도 동일 결정 사항.
- **L5-2 표시 잔무 일괄**: U1(R206 4건+중국어) · U2(FAB 겹침) · U3(국기 폴리필) · U4(kr-technical 초기 안내+y축) · U6(문구 잔존) · U8/U9 · L8(스케일 캡) · L9(IC 기준일 표기) · F3 설명문("TradingView" 잔존 참조).
- **L5-3** X1: 프록시 순서를 성공률 기반 동적 정렬(aio-proxy 우선) — 3연속 503 낭비 제거.
