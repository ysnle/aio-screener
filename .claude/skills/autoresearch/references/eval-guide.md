# Eval Guide (AIO 스킬용)

실제로 스킬을 개선하는 eval 기준 작성법. 거짓 자신감을 주는 eval 작성 금지.

---

## 황금 규칙

모든 eval은 yes/no 질문이어야 한다. 척도 없음. 느낌 검사 없음. 바이너리.

**이유:** 척도는 가변성을 증폭시킨다. 4개 eval을 각각 1~7점으로 채점하면, 총점이 실행마다 크게 달라진다. 바이너리 eval은 신뢰할 수 있는 신호를 준다.

---

## 좋은 eval vs 나쁜 eval

### 텍스트/분석 스킬 (integrate, data-refresh 등)

**나쁜 eval:**
- "분석이 충분히 심층적인가?" (너무 모호 — "심층적"이 뭔지?)
- "1~10점으로 통합 품질 평가" (척도 = 신뢰 불가)
- "키워드가 적절한가?" (주관적, 일관성 없는 채점)

**좋은 eval:**
- "TECH_KW에 3개 이상의 신규 키워드가 추가되었는가?" (바이너리, 측정 가능)
- "원문에서 언급된 모든 티커가 추출되었는가?" (바이너리, 검증 가능)
- "추가된 키워드 중 3글자 미만이 없는가?" (바이너리, grep으로 확인)
- "CHANGELOG.md 최상단에 새 항목이 있는가?" (바이너리, 구조적)

### QA/검증 스킬 (qa, knowledge-lint 등)

**나쁜 eval:**
- "QA가 철저한가?" (주관적)
- "버그가 없는가?" (범위가 너무 넓음)

**좋은 eval:**
- "<div> 수와 </div> 수가 일치하는가?" (바이너리, 명령으로 확인)
- "6곳 버전 문자열이 모두 동일한가?" (바이너리, grep으로 확인)
- "21개 페이지 중 Dead Page 없음이 확인되었는가?" (바이너리, 명시적 체크)

### 데이터/갱신 스킬 (data-refresh 등)

**나쁜 eval:**
- "데이터가 최신인가?" (기준 없음)
- "갱신이 잘 됐나?" (모호)

**좋은 eval:**
- "staleness 테이블에 22개 행이 모두 있는가?" (바이너리, 계산 가능)
- "CRITICAL 판정 항목이 0개 미처리인가?" (바이너리, 명시적)
- "배열 길이 일치 검증이 실행되었는가?" (바이너리, 실행 여부)

## 흔한 실수

### 1. eval이 너무 많음
6개 이상이면 스킬이 eval을 게임한다 — 실제 품질 개선 없이 테스트만 통과하도록 최적화된다. 시험 답안 암기와 같다.

**해결:** 가장 중요한 3~6개만 선택. 그것들을 통과하면 출력이 좋을 것이다.

### 2. 너무 좁고 경직됨
"정확히 3개의 티커를 포함해야 한다" — 기술적으로는 통과하지만 이상한 출력을 만든다.

**해결:** 실제로 중요한 특성을 체크하는 eval. 임의적인 구조적 제약 금지.

### 3. 겹치는 eval
Eval 1: "키워드가 R17 준수하는가?" + Eval 3: "3글자 미만 키워드가 없는가?" — 이건 같은 것이다. 두 번 계산하는 꼴.

**해결:** 각 eval은 독립적인 것을 테스트해야 한다.

### 4. 에이전트가 측정할 수 없는 eval
"사용자가 이 정보를 유용하다고 느낄 것인가?" — 에이전트는 이걸 신뢰할 수 있게 답할 수 없다. 거의 항상 "yes"라고 한다.

**해결:** 주관적 품질을 관찰 가능한 신호로 변환. "유용함"은 "구체적 수치 ≥3개 포함" 같은 것으로.

---

## eval 작성 3단계 테스트

eval을 확정하기 전에:

1. **두 다른 에이전트가 같은 출력을 채점해서 동의할 수 있는가?** 없으면, eval이 너무 주관적. 다시 작성.
2. **스킬이 실제 개선 없이 이 eval을 게임할 수 있는가?** 있으면, eval이 너무 좁음. 넓혀라.
3. **이 eval은 사용자가 실제로 신경 쓰는 것을 테스트하는가?** 아니면 drop. 중요하지 않은 eval은 중요한 eval의 신호를 희석시킨다.

## 템플릿

```
EVAL [N]: [짧은 이름]
질문: [yes/no 질문]
통과: [yes가 의미하는 것 — 한 문장, 구체적]
실패: [no를 유발하는 것 — 한 문장, 구체적]
```

예시:
```
EVAL 1: CHANGELOG 갱신
질문: CHANGELOG.md 최상단에 현재 버전 항목이 있는가?
통과: ## v{N} 형식 항목이 파일 상단 20줄 내에 존재
실패: CHANGELOG 갱신 없거나 이전 버전 항목이 최상단
```
