# Framework Extraction Contract

Use this reference to turn supplied research into reusable reasoning rather than copied conclusions.

## Q1-Q5 Extraction

Answer each question from the supplied material. Mark `not supported by source` instead of filling gaps.

1. **Thesis logic**: Why does the source differ from consensus or the obvious interpretation?
2. **Paradigm shift**: What old model is being replaced, and what new model explains the evidence better?
3. **Disconfirming variable**: What observable condition would make the thesis wrong or materially weaker?
4. **Structural mechanism**: What causal chain sits behind the event, announcement, or headline?
5. **Adjacent impact**: Which upstream, downstream, substitute, or complement changes if the thesis is true?

## Multi-Source Reconciliation

- Separate consensus from disagreement.
- Preserve source attribution for each claim.
- Do not blend contradictory views into a false average.
- Prefer official filings/data for factual claims and keep commentary as `REFERENCE`.
- Record observation date and currentness boundary for time-sensitive claims.

## Integration Shape

For each durable framework, retain:

- Claim or rule.
- Evidence and source tier.
- Causal chain.
- Bull/base/bear branch when supported.
- Invalidation condition.
- Target consumer: keyword routing, ticker/theme registry, chat context, knowledge base, or dated data surface.

Route current values, event probabilities, target prices, and changing market levels through `data-refresh` or an evidence artifact. Do not promote them as timeless framework facts.

## Binary Checks

| ID | Question |
|----|----------|
| FX1 | Is at least one supported Q1-Q5 framework extracted when the source contains one? |
| FX2 | Does every promoted framework retain evidence and attribution? |
| FX3 | Is an invalidation condition present or explicitly unsupported? |
| FX4 | Are multi-source disagreements preserved rather than merged away? |
| FX5 | Are transient values routed away from timeless framework storage? |
