# AIO Screener — Group 2 Route Audit: #breadth #sentiment #technical #macro #fxbond #options

Audited 2026-09-27. Live site: https://ysnle.github.io/aio-screener/ — live `version.json` origin tag observed as **v56.33** (browser tab title), while local working tree `version.json` reports **v56.58** ("legacy F-52 표본 gate와 live-core strict lineage 보강"). **The local codebase is ~25 versions ahead of the deployed site.** This matters: at least one bug documented below as already-fixed in `BUG-POSTMORTEM.md` is still visibly broken on the live site, meaning the fix has not been deployed yet. Treat "current code" (`src/ui/pages/*.js`) and "current live behavior" as two different things throughout — both are cited, with the gap called out.

All 6 routes share one architectural fact from `architecture/route-owners.json`: `lifecycleOwner`/`rendererOwner`/`dataOwner` are `native` for all six, but `narrativeOwner` is `legacy` for breadth/technical/macro/fxbond/options (only `sentiment` is fully native, including narrative). Charts are native everywhere except `technical` candle chart lifecycle (native per P833) — see per-route notes. This split matters for the audit: on breadth and technical in particular, a **native card** and a **legacy prose sentence right next to it** can independently go stale and disagree, because two different code paths write to the same page.

## Cross-route findings

1. **"판정 보류" is overloaded across the whole app**, not just sentiment — it's used for (a) genuinely missing data (VIX9D, breadth-50sma-readout on a bad day, MOVE/LQD/TLT), (b) present-but-reference-only data (HY spread badge, sentiment top badge when only one sub-metric blocks), and (c) a native/legacy plumbing bug where required inputs are visibly present elsewhere on the same page (technical market health, breadth header badge). A user cannot tell these three situations apart from the phrase alone. **Recommend a 3-tier vocabulary**: "미수신" (truly absent) / "참고용 · 판정 제외" (present, advisory-only) / never show "판정 보류" when the same page displays the inputs it claims are missing.

2. **Two live, currently-reproducible "data present nearby but the composite says missing" bugs** were found and directly verified via JS inspection: breadth's header badge + 50sma readout, and technical's market-health score. These share a pattern — a **native render path succeeds using one quote source while a legacy/composite path reads a different, stale/empty source**. Worth a focused investigation into whether `window._liveData` and whatever feeds `store.getState().analysis.technical` / `AIO.getCurrentBreadthEvidence()` are meant to be the same object and have drifted apart.

3. **One bug (breadth 50sma readout) is already fixed in the local codebase** (`_context/BUG-POSTMORTEM.md` LC-47/P1227) but is still live and broken on the deployed site (v56.33 vs local v56.58) — a **deployment-lag** issue, not a code issue. Worth checking whether other "already fixed" postmortem entries are similarly undeployed.

4. **#options is functionally redundant with #sentiment** (verified: all 3 live metrics are literal duplicates, confirmed by the codebase's own P1207 shared-observation note). **#macro and #fxbond legitimately share the treasury-curve model** (2s10s spread — verified as the same +0.36%p value, same model version `treasury-curve.v2`, on both pages) but are NOT redundant with each other; macro is about the causal transmission story (rates→CAPEX→breadth), fxbond is about the cross-asset positioning/carry read. That's a defensible split.

5. **Narrative ownership is uneven** (`sentiment` = native/single ViewModel; the other five = legacy prose). This isn't cosmetic — it's exactly why breadth and technical have live-contradiction bugs and sentiment doesn't (sentiment's single-revision-stamped render pass structurally prevents two code paths writing conflicting text about the same state). **Sentiment's architecture (`src/domain/sentiment/narrative.js` ViewModel pattern) is the template the other five routes should be migrated toward**, in priority order breadth and technical (where the bugs are) first.

## Proposed reorganization of the 6 routes for a family trader+learner

Current 6 separate nav entries: 시장 폭(breadth) / 투자 심리(sentiment) / 차트·기술 분석(technical) / 거시경제(macro) / 환율·채권(fxbond) / 옵션 분석(options).

Recommended reorganization:
