## 구조 보강안과 우선순위

1. **날짜와 단위의 결속**: 모든 비교·분해 입력에 observation period, publication/collection/attempt timestamp, currency, return basis를 결속한다. headline 합계가 맞아도 근거 기간이 틀릴 수 있으므로 합계 검사만으로 통과시키지 않는다.
2. **수집과 보존을 별도 상태로**: Cboe/DART처럼 숫자가 존재하는 것과 이번 실행이 성공한 것을 분리한다. 권한/미지원/미발행/일시 실패를 구분하는 receipt와 consumer 상태를 통일한다.
3. **불변 revision의 end-to-end 전달**: 파일명·row count·최대 날짜는 publication identity가 아니다. dataset revision/hash를 runtime cache, on-demand placement, 작업 실행기, AI context에 전달해 세대 혼합을 찾는다.
4. **공용 계약을 실제 호출에서 재사용**: budget/usage, candidate hashing, source/fact matching, currency/market 판정의 중복 구현을 줄인다. 큰 일괄 리팩터링보다 확인된 중복 쌍부터 계약 테스트로 고정한다.
5. **게이트의 증거 수준 명시**: inventory/regex/JSON/schema/source/mock/headless/browser/live를 각각 표기한다. source pin이 통과해도 실제 endpoint 실패·부분 publication·복원 실패는 별도 negative fixture가 필요하다.
6. **자료 수명주기**: canonical authoring source, generated projection, immutable object, audit evidence, cache, archive를 분리해 소유자와 생성 명령을 기록한다. 오래된 audit PASS를 최신 release 인증으로 재사용하지 않는다. 대용량 인벤토리·screenshots는 배포 입력과 분리하는 방안을 검토하되 이번 감사에서 삭제/이동하지 않는다.
