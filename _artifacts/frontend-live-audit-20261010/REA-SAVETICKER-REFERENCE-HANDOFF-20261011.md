# REA·SaveTicker 참조 조사 및 AIO 적용 판단

기록일: 2026-10-11 KST. **참조 조사 인계 완료 — 대표 화면/상태 검토, 전체 과거 콘텐츠 전수 열람은 아님.** 이번 산출물은 이 문서 하나다. AIO 코드·버전·설정·generated 문서·기존 인계 문서는 수정하지 않았다. REA 설치/실행·스킬 적용·회원가입·유료 결제·알림 구독·개인 투자정보 입력은 하지 않았다. 실제 열람 범위와 미검증 항목은 끝의 커버리지 표를 따른다.

## 기준선과 판정 방식

- 시작 시 git status/version.json 확인: 로컬 v57.32, 여러 dirty 프론트엔드/운영 변경 존재. CURRENT-STATE는 19 legacy route를 표시한다. 채택안은 고정된 8-screen 통합 방향에 배치하며 새 최상위 화면을 무분별하게 늘리지 않는다.
- 공개 SaveTicker를 실제 브라우저로 방문한다. 첫 537px 창은 화면 확인에 한계가 있어, AIO의 desktop-only 기준 비교를 위해 1440×900으로 임시 검사한다. 종료 시 원래 크기로 복귀한다.
- `관찰`은 실제 DOM/화면/상호작용, `문서`는 REA 공식 문서, `소스`는 실제 공개 코드, `추론`은 그 근거에서 도출한 AIO 설계 제안이다. 소개 문구를 실행 검증으로 승격하지 않는다.
- ‘모든 화면’은 현재 공개 내비게이션에서 접근 가능한 화면/주요 상태를 조사하고, 로그인·권한·동적 과거 목록·외부 기사 등 읽지 못한 범위도 명시하는 방식으로 다룬다. 전체 역사 기사와 숨겨진 회원 화면을 모두 읽었다는 표현은 사용하지 않는다.
- SaveTicker 기사에서 본 시사/가격/예측은 제품 표현 조사 대상이며 사실 검증된 AIO 투자 데이터가 아니다. 원문 전체를 복사하지 않고 정보 구조와 읽기 흐름을 분석한다.

## 중간 관찰 1 — 공개 뉴스 첫 화면

주소: [SaveTicker 뉴스](https://saveticker.com/news). 웹 텍스트 도구는 403을 받았지만 실제 브라우저에서는 뉴스 화면을 읽었다. 이를 사이트 전체 접근 불가로 단정하지 않는다.

- 고정 좌측 뉴스/커뮤니티/증시/캘린더/내 정보/알림 내비게이션과 상단 검색, 로그인 버튼. 우측 시장/관심/캘린더/스크랩 보조 패널이 별도로 있다.
- 상단 안내 배너 → 날짜가 붙은 종목 트렌드 → 출처 탭 → 카테고리 칩 → 오늘 주요뉴스 가로 카드 → 시간순 뉴스 목록으로 연결된다.
- 오늘 주요뉴스는 긴 제목·출처·분류·시각·관련 ticker chip·조회 수를 사용한다. 뉴스 목록도 출처/시간/제목을 우선하고 본문은 상세 진입에 맡긴다.
- `새 뉴스`를 누르는 업데이트 접점, 출처 필터와 `전체 · 최신순`, 새로고침·맨 위로가 보인다. 우측 패널은 기본 축소 상태다.
- 장점 후보: 본문을 한 화면에 늘어놓지 않는 스캔 구조, 기사에서 관련 종목으로 이어지는 맥락, 선택 시 열리는 보조 정보, 미확인 보도/AI 표시.
- 반례 후보: 상단 안내(9/11), 트렌드 날짜(10/9), ‘오늘’ 주요뉴스 시각과 실시간 상대 시각이 한 화면에 있어 기준 날짜를 더 명확히 할 필요가 있다. 실제 stale 여부는 아직 검증하지 않았다. 큰 주요뉴스 카드와 긴 목록은 같은 사건 중복·카드 제목 말줄임·조회 수가 중요도처럼 읽히는 문제도 살펴야 한다.

## 조사 범위 설정

뉴스 상세·주요뉴스 전체·출처/정렬/검색·종목·시장/관심/캘린더/스크랩 패널·커뮤니티·증시·캘린더·내 정보/알림·로그인 경계 및 공개 출처 안내를 조사 범위로 설정했다. 각 항목의 실제 검토 깊이는 마지막 커버리지 표에 기록했다. REA는 website/JavaScript evidence와 소스 결과 계약을 독립 조사했고 기존 도구로 충족 가능한 부분과 새 의존성이 필요한 부분을 구분했다.

## 중간 관찰 2 — 세션 경계와 기사 상세

- 앱 브라우저 비로그인 상태에서는 뉴스 상세, SAVE 리포트 탭, 우측 패널 확장이 로그인 안내로 막혔다. 커뮤니티·증시도 로그인 안내 화면을 확인했다. 이는 해당 세션의 접근 제한이며 서비스 오류 판정이 아니다.
- 사용자가 “현재 열려있는 Chrome창에서는 로그인 해놨는데? 아님 내가 여기 브라우저에서 로그인해줘?”라고 안내했고, 이어 “Chrome에 SaveTicker 탭이 열려 있음”이라고 확인했다. 기존 Chrome의 해당 탭을 연결했고 프로필 메뉴가 보이는 로그인 상태에서 상세를 읽었다. 따라서 앞선 로그인 제한을 최종 조사 중단 사유로 남기지 않는다.
- 파이낸셜주스의 AI 묶음 상세를 실제 열었다. 출처·분류·묶인 헤드라인 수 → 상대/절대 시각 → 제목 → 번역/원문 선택 → 짧은 AI 요약 → 시간별 개별 헤드라인 → 출처/권리 안내 → 반응/댓글 순서다. 같은 사건 2개 헤드라인의 순서를 세로 선과 노드로 표시하고 최신 항목을 구별한다.
- 원문 버튼을 눌러 영문 헤드라인으로 바뀌는 것을 확인했다. 요약은 번역 모드에 표시되고, 원문 모드에는 개별 원문이 보인다. 원문 대조가 없는 AI 요약보다 검토 가능성이 높다. 실제 번역 정확성 전수 평가나 원 공급자의 기사 전체 검증은 하지 않았다.
- 상세 하단에는 제휴 헤드라인의 AI 번역이라는 설명과 재배포 제한 안내가 있다. SaveTicker 화면 접근이 AIO에 기사·데이터를 수집·재사용할 권리를 주는 것은 아니다. 이 보고서는 상세 본문을 전재하지 않는다.
- 원문이 두 줄인 사례에서는 요약 상자+요약 제목+요약 bullets가 원문보다 길어질 수 있다. AIO는 모든 짧은 속보에 AI 요약을 덧붙이기보다 중복 제거·정정 이력·사건 의미가 추가될 때만 요약을 보여주는 것이 낫다.
- 주요뉴스 전체보기는 날짜 이동과 일별 묶음 목록을 제공한다. 기준 선택은 2026.10.10인데 보이는 묶음은 10/9·10/8·10/7이다. 마지막 거래일/선정 기간/표시 시간대인지 설명 확인 전에는 stale 버그라고 확정하지 않는다. 날짜별 확장 방식 자체는 AIO 오늘 화면의 지난 브리핑 탐색 후보다.
- 출처 선택은 5개 중 선택 수, 모두 선택, 적용 버튼을 제공한다. 기간은 최근 4시간/24시간/7일/1개월과 사용자 지정, 정렬은 최신/조회 수다. 사용자 지정의 날짜 입력·캘린더·닫기·미선택 적용 비활성 상태를 읽었다. 조건 UI 확인과 실제 모든 조건의 결과 정확성 검증은 구분한다.

## 중간 관찰 3 — 로그인 후 데일리 리포트

참조: [10월 9일 리포트 상세](https://saveticker.com/report/793). 날짜 카드 클릭으로 이동했고, 다운로드하지 않고 브라우저에 표시된 문서를 스크롤해 읽었다. iframe 문서는 접근성/DOM에서 본문을 읽지 못해 스크린샷의 실제 페이지로 확인했다. 화면만으로 전체 페이지 수를 확정하지 않았다.

- 표지 → 시장 지도/업종 막대 → 전일 지수·금리·달러·에너지·경제지표 → 심리 게이지/VIX 차트 → 시간별 속보 목록 → 주제별 뉴스 묶음 → 당일 주요 기사로 이어진다. 날짜별 읽기 흐름과 출처가 있는 시각 자료를 조합한다는 점이 유용하다.
- Finviz 시장 지도는 시장 전체의 분포를 한눈에 보여주지만 작은 종목 문자까지 읽기는 어렵다. 업종 막대는 음수 값도 오른쪽으로 뻗고 0~양수 눈금을 사용하는 화면을 관찰했다. 이 형식은 상승/하락을 색과 부호에 의존하므로 AIO에서 복제하지 않고 0을 중심으로 좌우 방향을 나누는 막대를 추천한다.
- CNN 게이지와 VIX의 구글 차트가 표시된다. 외부 출처 명시가 있더라도 AIO의 지표 사용 권리·갱신 기준·입력 정의 검증이 별도로 필요하다. 단일 게이지를 근거 없이 AIO 종합 점수로 확장하면 안 된다.
- 시간표는 흰 글자/노랑 강조/청록 분류를 쓴 이미지형 목록이다. 많은 항목과 배경 일러스트는 읽기 집중과 우선순위 판단에 방해가 될 수 있다. AIO에는 상위 사건 3~5건, 시간·사실·정정만 남기고 상세를 펼치는 방식이 적합하다.
- 기사 부분은 한글 제목, 영문 제목, 출처가 있는 첫 문장, 맥락 bullets로 구성된다. AI 투자, 부품 공급, 수요, 통신 경쟁, 보험 정책, 제재, 광고 플랫폼 경쟁, 자금 조달, 물류 자동화, 반도체 실적, 금리, 전문가 의견의 실제 문단을 읽었다. 단순 제목 복사보다 배경과 후속 확인 대상을 함께 설명하는 구조는 유용하다.
- 일부 문단은 전달 동사(보도·설명·지적·전망)를 반복하고 한 bullet이 여러 줄로 이어진다. 작성 주체가 사람/AI인지는 화면만으로 판정할 수 없다. ‘AI 같은 느낌’은 저자 추정 대신 반복 어미·긴 문장·추상적 의미·원문 대비 추가 가치로 평가해야 한다.
- 한글과 영문 제목의 병렬 표기는 대조에 도움이 되지만 기본 읽기에는 중복이다. AIO는 한글을 기본으로 두고 원문 제목/번역 대조는 요청 시 펼치는 편이 읽기 밀도를 줄인다.
- 문서의 페이지 나눔과 큰 여백, 반복 표지/반복 섹션 머리말은 PDF 배포에는 쓰일 수 있으나 대시보드의 빠른 탐색에는 비효율적이다. AIO는 HTML 본문·절별 앵커·검색 가능한 표/차트를 기본으로 하고 별도 PDF 생성은 사용자 요구가 있을 때 후순위로 둔다.
- 문서 수치·시사 내용은 참조 제품의 서술을 읽었다는 증거이며 AIO에 입력 가능한 검증 데이터가 아니다. 기사 전문·외부 지도·차트 이미지를 이 파일에 복제하지 않았다.

## 중간 관찰 5 — 검색·로이터 번역/원문 대조

- NVDA 검색은 회사 자체와 이름에 NVDA가 포함된 별도 ETF를 각 회사명/ticker로 구분해 보여준다. 결과가 관련된다는 것과 동일 issuer라는 것은 다르다. AIO는 exact registry match로 회사를 확정하고 관련 회사는 별도 목록으로 표시해야 한다.
- 검색 목록에는 동일 사건의 단신·초보·2보·3보가 별도 카드로 반복된다. 속보 아카이브에는 이력이 필요하지만 오늘 화면에서는 사건별 대표 제목과 업데이트 수로 축약하고 상세에서 변경 이력을 읽는 편이 효율적이다. 의미가 비슷한 제목만으로 묶으면 별개 사건을 합칠 수 있으므로 source story ID와 issuer·사건·시각 및 정정 관계가 필요하다.
- 로이터 기사 하나의 번역 본문과 원문을 실제 읽었다. 제목→관련 회사→AI 요약→긴 본문→기자/원문 등록 시각→제휴/재배포 안내→관련 회사 반복→구독 배너→반응·댓글 순서다. 번역/원문 버튼은 영문 제목과 본문으로 전환되며 원문 모드에서는 AI 요약이 사라진다.
- 요약은 혐의와 법원 절차를 압축했지만 본문에 있는 회사 측 입장·회사와 개인의 법적 지위 차이는 별도 문단에 있다. 이 관찰은 요약의 모든 문장이 틀렸다는 판정이 아니다. AIO 요약 검수는 주체, 주장 출처, 혐의/확정 구분, 반대 입장, 시간 조건을 유지해야 한다. 긴 본문은 대조 가능하지만 상단 요약만 읽는 사용자에게 중요한 제한 조건이 사라지면 안 된다.
- 한글의 ‘3보’와 원문의 ‘UPDATE 2’가 서로 다른 표기였다. 공급자별 최초보/업데이트 번호 계산을 확인하지 못했으므로 오류라고 확정하지 않는다. AIO가 자체 번호를 붙인다면 공급자의 번호와 자체 업데이트 횟수를 구별한다.
- 회사 칩과 구독 안내가 반복되는 상세 하단은 서비스 참여에는 유용할 수 있지만 AIO의 연구 목적에는 과밀하다. 관련 회사는 한 번, 원문 링크와 다음 확인 사건은 가까이, AI 주의사항은 전역 안내+필요시 상세로 정리하는 제안이다.
- 존재하지 않는 공개 테스트 문자열로 검색해 ‘검색 결과가 없어요’와 검색어 변경 안내를 확인했다. 결과 없음이 오류/로딩과 다른 상태로 표시되는 점을 차용한다. 모달 닫기 직후 입력을 한 번에 진행한 첫 시도는 기존 검색어가 남았으므로, 최종 입력과 새 검색 결과 제목을 확인한 두 번째 시도만 빈 결과 증거로 인정했다.
- 관심 뉴스 탭은 빈 상태에서 종목/태그/키워드 추가 이유와 설정 진입을 안내했다. 설정 저장이나 실제 구독 추가는 실행하지 않았다.
- SAVE PICK의 TSMC 실적 기사에서는 분기/월간/누적 매출·통화 단위를 나눴으나 과거 월별 숫자가 텍스트 목록으로 길게 이어졌다. 추세 차트와 실제/예상 비교 막대가 이해를 도울 후보이며, 검증된 공식 구조화 데이터가 전제다. 본문에서 보이는 긍정/부정 투표는 독자 반응이며 실적의 객관적 품질·향후 수익률이 아니다. 댓글의 ‘상회/하회’ 상반된 주장만으로 기사 오류나 정정 이력을 확정하지 않는다.

- PR 뉴스와이어 공개 아카이브에서 기업 PR·보도자료라는 성격, 최신순·3페이지 탐색과 재배포 제한 안내를 읽었다. AIO의 출처 분류는 통신사 독립 보도, 기업 발표, 공시, 소문, 개인 의견을 구별해야 한다. PR 대량 공급이 뉴스 coverage 개선을 자동 의미하지 않는다.

### 도입 범위와 비용 판단

1. 먼저 REA-02/03/04/07을 기존 문서·발견 원장 방식에 반영하는 제안이다. 이는 이번 문서의 분석이며 QA 도구 코드를 변경하지 않았다.
2. 다음은 REA-05/06의 대표 여정 비교 계약. 기존 qa-runner/브라우저 도구에 필요한 최소 항목만 보완한다.
3. REA-01/08/09는 운영 증거 연결을 보완할 후보다. 전체 MCP를 AIO 런타임에 넣거나 전부 수집하는 방식은 보류한다.

[현재 소스의 의존성](https://github.com/morluto/rea/blob/603d04ee3ac6ed496f84478164f832a9b5ce3b91/package.json)은 Node `^22.19.0 || ^24.11.0 || >=26.0.0` 및 MCP/Babel/Playwright core/archive/PTY/schema 도구군을 포함한다. 네이티브 바이너리·Electron·.NET·APK 조사 엔진은 AIO 정적 ESM/Worker 제품에 직접 필요하지 않다. ‘Anything’라는 소개가 미적 감각·한국어 문구·차트 의미·투자 해석을 자동 검증한다는 증거는 아니다.

[MIT 라이선스](https://github.com/morluto/rea/blob/603d04ee3ac6ed496f84478164f832a9b5ce3b91/LICENSE)는 REA 코드의 이용 조건이다. 분석 대상 기사/데이터/디자인 자산의 재사용 허가는 아니다. 실제 REA 코드를 차용한다면 저작권/허가문을 보존해야 한다. [README](https://github.com/morluto/rea/blob/603d04ee3ac6ed496f84478164f832a9b5ce3b91/README.md)는 로컬 분석을 설명하지만 결과를 읽는 모델의 비용·정책은 별도다. 도입 시 AI 비용이 사라지거나 AIO Worker 원장에 자동 포함되지는 않는다. 설치/실행 없는 현재 조사에서는 도입 효율을 실측 PASS로 표현하지 않는다.

## 전체 인터페이스·디자인에 대한 판정

아래 평가는 실제 화면의 구조를 근거로 한 디자인 판단이다. SaveTicker의 다크 테마·보라색 강조를 그대로 복사하거나 AIO의 현재 아이보리/잉크·타이포그래피를 교체하라는 뜻은 아니다. AIO 스타일 근거는 기존 [시각 검토 자료](./VISUAL-INTERFACE-REVIEW.md)이며, 이번에 Claude의 최신 변경 전체를 다시 라이브 인증하지 않았다.

## 8개 화면의 시각적 설명 후보

이 표는 SaveTicker에서 관찰한 패턴과 AIO의 고정 방향을 연결한 설계 제안이다. ‘현재 AIO에 없다’는 새 결함 판정은 아니다. Claude의 실제 구현을 먼저 대조한 뒤 이미 충족된 항목은 중복 작업하지 않는다.

| AIO 화면 | 기본 읽기 질문 | 적합한 시각 형태 | 피할 오해·적용 전제 |
|---|---|---|---|
| 오늘 | 무엇이 달라졌고 다음에 무엇을 확인하나 | 대표 사건 3~5개, 변경 타임라인, 다음 7일 발표 목록 | ‘오늘’의 session date 명확히. 일반 배경 설명과 같은 사건 제목 반복을 줄임 |
| 시장 상태 | 상승이 넓게 퍼졌나, 어떤 증거가 엇갈리나 | breadth 시계열, 업종 0 중심 막대, 분포/heatmap | 종합 점수/감정 게이지로 결론 대신하지 않음. universe/가중/축 확인 |
| 거시 | 발표값과 예상·추세가 어떻게 다른가 | 실제/예상/이전 비교, 단위가 붙은 시계열, 발표 일정 | 인플레→금리→기업 영향 화살표는 조건부 해석. 실제 관측과 예측 구분 |
| 종목 | 가격·실적·뉴스·공시가 같은 회사를 설명하나 | 가격+거래량, 선택 가능한 사건 표식, 실적 small multiples, 공시 타임라인 | 같은 entity/시간 기준. event marker는 인과 증명 아님. 목표가·매매 지시 제외 |
| 테마 | 어떤 회사가 어떤 사업 관계로 연결되나 | 검증된 공급/수요 관계도, 테마 내부 분포·추이 | 관계 유형·근거·일자 필수. 이름 유사성만으로 연결 금지. 한국 테마 보존 |
| 스크리너 | 조건을 통과/제외한 이유가 무엇인가 | 활성 필터와 결과 수, 조건별 근거, 비교 표/분포 | 설명 없는 합성 등급 금지. 결과 0/입력 없음/데이터 없음 구분 |
| 포트폴리오 | 노출이 어디에 모이고 어떤 이벤트가 예정됐나 | 노출 막대·구성표, 보유 관련 일정, 메모 당시 시각 | 사용자 실제 값은 공개 증거에 넣지 않음. 부족한 데이터로 리스크 점수 생성 금지 |
| 배우기 | 개념과 실제 관측을 어떻게 연결하나 | 간단한 과정도, 용어와 chart annotation, 사실/해석 구분 예시 | 장식용 다이어그램보다 관계 3~5개부터. 정적 지식은 source 변경 시 갱신 |

시각화는 한 그림이 한 질문에 답하게 한다. 색 외 부호/라벨/선 종류를 제공하고 축·단위·기간을 읽을 수 있어야 한다. 모든 텍스트를 이미지로 바꾸면 검색·접근성·원문 대조가 나빠질 수 있다. 시장 열지도는 전체 구조를, 타임라인은 변경 순서를, 비교 막대는 차이를 설명할 때 사용한다. 단일 숫자나 아이콘을 늘리는 것은 추세 설명을 대체하지 않는다.

## 다른 Harness를 위한 작업 연결과 검증 순서

1. 이 문서와 기존 HANDOFF/운영 인계/8화면 구조 제안을 함께 읽고 현재 `git status`, version, route registry와 Claude 작업 소유권을 확인한다. 이번 문서는 구현 대상 목록을 추가 제안하며 기존 발견의 해결 상태를 다시 열거나 완료로 바꾸지 않는다.
2. ST-01~05와 REA-02/03/04/07을 기존 구조에서 충족하는지 먼저 대조한다. 새 프레임워크 설치보다 동일 사건 중복·entity 오연결·출처/기간 누락을 먼저 해결한다.
3. source/artifact→정규화→consumer→route render→상태 표시에 같은 계약을 적용한다. 공유 Worker의 AI 예산/예약/정산을 우회하는 별도 기사 번역 호출을 만들지 않는다. 원문 선택마다 즉시 AI 호출하는 구조 대신 허용된 소스·내용 해시·언어·모델 기준 캐시를 검토한다. 내용 해시에는 build/review 시각을 넣지 않는다.
4. 일정/소유지분/지식/가격의 갱신 주기를 각각 정한다. 13F는 분기·공시 시즌, 13D/G는 사건 기반 가벼운 poll, 지식은 소스 변경, score는 직전 미국 정규장 종가. 모든 것을 동일한 실시간 주기로 돌리지 않는다. 데이터 producer는 GitHub Actions에서만 실행한다.
5. 각 후보를 구현할 때 발견별 `ID, SHA, 화면/상태, entity, 초기 조건, 행동, 기대/실제, 증거 위치, observed/inferred/unknown, 소스·시점·제한, 완료 기준`을 유지한다. 실제 코드 차용과 설계 아이디어 차용을 구별한다.
6. 대표 여정은 오늘→사건→종목→공시 원문, 검색→exact issuer/0건, 거시→발표 대기/실제/개정, 테마→관계 근거, 필터→0건/복구, AI→응답/예산 제한/불완전 응답이다. 회귀 gates와 실제 Chrome 증거 및 한국어 내용 검수를 각각 기록한다.
7. 두 Harness가 같은 main을 수정할 때 쓰기 소유권을 다시 합의하고 disjoint 변경을 유지한다. 이번에 implementation branch/worktree를 만들지는 않았다. 실제 병렬 코드 작업이 필요하면 repository의 worktree 규칙을 따른다.
8. 완료/QA 통과와 commit/push/deploy를 구별한다. GitHub CI/Pages/Worker/API 작동은 실제 해당 SHA·배포·응답으로 검증해야 하며 이 참조 조사로 보증되지 않는다.
