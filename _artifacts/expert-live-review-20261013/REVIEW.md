## 브리핑·뉴스에서 추가로 확인한 문제

### X20 / 높음 / B+S — AI 브리핑의 자체 기준과 근거 연결이 없음

실제 부모 제목은 ‘10/9 미국 종가 기준 · 자동 해석’이다. 그 아래 AI 해설은 10/12 20:16 KST 생성본으로, 미국 지수·10년물의 10/9 관측, WTI·DXY의 10/12 20:06 장중 관측, 코스피의 10/12 종가를 섞는다. 장중 WTI +1.26%와 deterministic 표 +0.4%는 서로 다른 관측을 읽은 것이므로 숫자 자체의 모순으로 집계하지 않는다. 10년물 +0.25%도 금리의 상대 변화이며 약 +1.3bp와 산술적으로 맞는다. 문제는 AI의 기준과 단위가 부모 제목만으로 이해되지 않는다는 점이다.

`briefing-read.js:130–131`, `index.html:6616`, `js/aio-core.js:3411–3422`에서 별도 AI sink를 확인했다. server 선택은 verified·한국어 여부를 검사하고 자체 나이/basis admission은 하지 않는다. 표시 시각은 실제 artifact 생성 시각 대신 렌더 시점의 현재 시각이다. 실제 [90b7eec7]/[regime-context]가 본문에 남고 제거 정규식은 긴 ID만 인식한다. `js/aio-data.js:6021–6031` loader도 metricEvidence/claims를 해당 sink로 전달하지 않는다.

AI 카드 하나에 자체 기준일·생성 시각·혼합 관측 범위를 표시하고, 원장 ID를 사용자용 근거 펼치기에 연결해야 한다. 데이터 revision/basis가 바뀌면 과거 AI 해설을 현재 해석으로 재사용하지 않는 admission이 필요하다. 새 숫자나 긴 면책 문구를 더할 문제가 아니다.

### X21 / 중간 / B+S — 뉴스의 표시 수집 창과 실제 목록이 다름

실제 top은 ‘10/11 08:00~10/12 08:00 KST’, 중요 뉴스 제목은 ‘10/12 08:00까지 24시간’인데 목록에는 10/12 23:00·18:30 등이 표시된다. `src/ui/pages/news.js:73–79` header는 `_serverDataMeta.newsCycle*`를 사용한다. feed는 `js/aio-data.js:11327–11336`에서 서버 cut이 publication/freshness 조건을 통과하지 않으면 wall-clock의 최신 완료 08시 창으로 전환하고 그 창을 `model.newsCycle`로 반환한다(:11535).

정확히 어떤 runtime fallback 사유가 발생했는지는 미확인이다. 그러나 화면 표시 창과 기사 시각의 충돌은 직접 확인했다. header·중요 뉴스 마감시각·집계는 실제 렌더 모델의 `newsCycle`에서 파생하고, 마지막 서버 수집 창은 별도의 수집 상태로 표시해야 한다. backstop도 모델 창 밖의 기사를 넣을 수 있는 분기(:11354–11355,11450–11452)가 있어 하나의 완료 창에 서로 다른 item-cycle을 섞는지 확인해야 한다.

## AI 질문 대상에서 추가 확인한 문제

### X22 / 중간 / L+O+S — 역할·산업 약어가 기업 질문으로 바뀜

실제 시장 AI 답변 뒤에는 ‘PM의 성장률·마진·밸류에이션’, 테마 답변 뒤에는 ‘HW 관련 최근 공시·뉴스’가 제안됐다. 원 질문의 PM은 운용 담당 역할이고 HW는 서버 하드웨어 분류다. 답변 본문에서 잘못된 발행사 수치를 만들었다는 주장은 아니다. 후속 질문과 데이터 요청의 분석 대상이 바뀌는 문제다.

최신 `js/aio-chat.js:2525–2547`의 `_extractTickers`는 bare 대문자2~5글자를 추출하며 이 두 표현은 제외되지 않는다. 같은 현재 함수를 추출 실행해 역할 문장→PM, 산업 문장→HW를 재현했다. `:5142–5158`의 후속 질문은 detectedTickers 첫 항목을 그대로 기업으로 사용하고 `:5400–5420`은 추출된 종목이 있으면 강제 최신 데이터 조회도 요청한다. 선택 종목·명시적 티커·정확한 발행사와 질문 맥락으로 기업 대상이 확정된 뒤 기업 질문을 만들어야 한다. PM이라는 실제 티커 자체를 금지하거나 다른 발행사로 고쳐 쓰는 해결은 적절하지 않다.
