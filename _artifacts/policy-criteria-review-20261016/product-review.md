# 제품·UX·접근성·권리·규제 및 R240–R469 규칙 자체 감사

검토일: 2026-10-16 KST. 기준 버전 v57.82. 소스 상태: 사용자 소유 dirty 변경이 많은 현재 작업 트리를 읽었다. 기존 코드·정책·생성물·QA·Git에는 변경을 하지 않았다. 이 문서는 규칙 자체의 타당성에 대한 독립 판단이며 구현 완료, 법률가 승인, WCAG 적합성 인증, 데이터 공급자 허가를 대신하지 않는다.

## 결론

정직한 자료 경계·동일 지표의 일관성·결측 보존·권한 없는 외부 실행 금지·증거 범위 구분은 유지하는 편이 합리적이다. 그러나 과거 사고의 해법을 영구 제품 규칙으로 굳힌 항목, 법·표준·계약과 자율 기준을 섞은 항목, 설명 기능까지 예측력 인증으로 묶는 항목은 개정해야 한다. 8개 화면·3초 이해·한 카드 한 상태·persona별 5인 사용자 연구·7/30일 soak·특정 schema/파일명·분량 하한은 객관적 최선으로 입증된 법칙이 아니다. 현재 사용자와 위험에 맞춰 검증할 선택이다.

판정은 유지 / 조건부 유지 / 개정 / 폐기 / 역사 기록 / 본문 미확인으로 구분한다. 폐기는 코드 기능을 없애라는 실행 지시가 아니라 해당 영구 규칙의 폐기 후보 제안이다. 개정·폐기에는 소유자 판단이 필요하며 이번 감사에서 기존 규칙은 바꾸지 않았다.

### D. 접근성 기준을 실제 WCAG 요건으로 고친다 — P1/P2

공식 기준:
- [WCAG 2.2 본문](https://www.w3.org/TR/WCAG22/)
- [2.5.8 target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum): AA는 24×24 CSS px 또는 정해진 spacing·inline·essential 등 예외를 다룬다. 44px를 모든 경우의 AA 의무로 오인하지 않는다.

- [4.1.3 status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): 중요한 상태를 적절히 전달하는 조건이지 aria-live를 문서 전체 몇 개로 제한하는 기준은 아니다.
반례: 12px 저대비 숫자·확대하면 사라지는 표는 10px gate를 통과할 수 있다. 반대로 촘촘한 시각의 점은 essential/대체 기능으로 평가할 수 있다. 전역 live region 개수는 조용해도 AI 완료를 전달하지 못하는 UI를 승인할 수 있다.
개정안: font 크기·hit area는 자율 디자인 목표와 표준을 분리한다. 실제 사용자 장치·전체 작업·키보드·보조기기에서 완료/실패 상태를 평가한다.
수용 기준: 주요 작업에서 접근성 방해가 없고, 표준별 예외 근거가 기록되며 자동 행렬을 수동 보조기기 적합성 인증으로 올리지 않는다.

근거: AGENTS.md:31–39; R328/R329/R331/R424/R425/R426. 8화면은 업무 묶음의 합리적 출발점이나 객관적 최적 개수는 아니다. 3초 이해는 원하는 제품 효과이며 모든 복잡한 시나리오의 인지시간 상한이 아니다.

### H. 콘텐츠 양식을 의미·효용 중심으로 줄인다 — P2

## 주장하면 안 되는 결론

이번 감사는 법규가 AIO에 확정 적용된다거나 면제된다고 결론 내리지 않는다. 국가법령정보센터의 자본시장법 제101조 최신 직접 URL은 도구에 본문이 오지 않아, 2024 금융위 설명을 2026 전체 현행법의 확정 대조로 승격하지 않았다. 데이터 권리자나 공급자의 허가를 얻지 않았고 민감 자료·수탁 계약을 보지 않았다. 각 maintained 규칙은 현재 목적에서 합리적인 원칙이라는 뜻이며 객관적 유일 최선·실구현 적합·live 통과를 뜻하지 않는다. 이번 산출물은 기존 정책을 자동 변경하거나 기능 삭제·통합을 승인하지 않는다.
