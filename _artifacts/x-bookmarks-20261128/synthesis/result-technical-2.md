## 2. 상·중 방법 상세

### #1 FTD 정의 (상, 고칠 것)
- 규칙(글): 랠리 시도 저점이 지켜진 채 4일차 이후 지수가 전일보다 많은 거래량으로 **+1% 이상** 오르면 FTD(2124875682576531796). 반증: 반등 후 저점 하회(2123425928550191198).
- 지금 코드: `rally-attempt.js:47-51` day ≥ 4, `gainPct >= 1.25`(`thresholds.js:3`), 거래량 > 전일. 대상 지수는 나스닥 종합(`market-charts.js:89-92`).
- 차이: 임계 1.25%는 이 묶음 글에 없다(IBD 관례로 보이나 출처 기록은 코드 주석에 없음). 글의 +1%와 다르다. 바꿀지(1% / 1.25% 병기) 결정이 필요하고, 바꾸면 `RALLY_COUNT_MODEL` 재기록이 필요하다(`rally-attempt.js:19-20`).
- 화면: 나스닥100 카드 '거래량' 줄(지금 그대로)에 규칙 문장이 이미 있음(`rally-attempt.js:103`).
- 검사로 지킬 사실: "FTD 판정일의 종가 상승률은 규칙 임계 이상이고 거래량은 전일보다 크다"를 history 행에서 재계산해 일치.

### #2 분배 우세 중 FTD (상)
- 규칙(글): 최근 수 주간 하락일 거래량이 상승일 거래량을 계속 웃돌면 FTD가 나와도 실패 가능성 높음으로 표시; 분배일이 줄고 상승일 거래량이 우세해지면 안정(2120544805310632401). 임계 '수 주'의 숫자는 글에 없음.
- 필요한 계열: 지수 일별 상승일·하락일 거래량 합(25세션). S&P 500은 `distributionDays`가 있고, 나스닥·QQQ는 카드 봉 거래량.
- 지금 코드와 차이: S&P 카드는 분배일 수(`market-charts.js:80-87`), 나스닥 카드는 FTD 상태(`:88-92`) — 같은 화면에서 지수마다 다른 거래량 판정을 하나씩만 보인다. 두 판정을 같은 지수에서 함께 읽지 않는다.
- 화면: 지수 카드마다 같은 모양의 '거래량 상태' 두 칸(분배일 n/25, 상승/하락 거래량 비) — 종목 차트의 상승일/하락일 거래량 배수 `chart-analysis.js:264`를 지수 봉에 그대로 쓰면 정의가 하나로 맞는다.
- 반증: 분배일 감소와 상승일 거래량 우세 전환.
- 검사: "FTD 확정 표시가 뜬 날 분배일 수가 경고선(`RULES.leadership.distributionDaysAt`=6) 이상이면 같은 카드에 분배 우세 문구가 함께 있다".

### #4 약세 속 과매도 반등 분류 (상)
- 규칙(글): 지수가 크게 올라도 하락하는 10일선 아래이고 거래량이 전날보다 적으면 저점 확정이 아니라 약세 속 과매도 반등(2125236108904575008). 과확장 하락 뒤 급반등은 '반등', 그룹·시장 확인과 며칠 뒤 주요 가격대 유지가 나와야 '새 추세 후보'(2110863106398150855). 갭으로만 오른 반등은 첫 눌림 지지 확인 때만 추세 반등 후보(2125082313528856961, 4시간봉).
- 필요한 계열: QQQ·SPY 일봉, 10일 SMA와 그 기울기, 일 거래량.
- 지금 코드: 반등 단계(시도/회복/실패)는 `rebound.js`(Codex 기록, 이번에 열지 않음), 바닥 체크 `market-read.js:1001-1038`(소진·회복 각 4항목). 10일선 기울기와 반등일 거래량 비교 항목은 어디에도 없다.
- 화면: 지수 카드 아래 반등 트랙(`charts.js:107-109`)에 한 줄 판정 '과매도 반등 / 확인 대기'와 근거 두 칸(10일선 방향, 반등일 거래량 대 전일).
- 반증: 후속 매수일(FTD) + 시장 폭 개선 + 건전한 베이스 돌파(글).
- 서로 부딪히는 글: 2125236108904575008은 큰 하루 반등 자체를 저점 근거로 보지 않고, 2121226324413214935는 넥라인 종가 돌파를 단기 반등 시나리오 우세로 본다 — 두 글 모두 '추세 전환'은 아니라는 데서 일치하므로 상태어를 '반등'과 '추세 회복'으로 분리하면 충돌이 없다.
- 검사: "반등일 종가 < 10일선이고 10일선이 5세션 전보다 낮으며 거래량 < 전일이면 상태어는 '추세 회복'이 될 수 없다".

### #5 주도주 확인(FTD 뒤 돌파 수, 주도주 부재) (상)

- 화면: FTD 상태 옆에 '확인 단계' 3칸 막대(FTD → 돌파 대기 n → 실제 돌파 n), 분모(판정된 종목 수)를 작게(visuals-스크리너 2124565821137748222의 '타일마다 분모·조건' 방식).

- 검사: "돌파 수는 그날 setup 상태가 ready였고 다음 세션 피벗 위 마감한 종목 수와 같다(재계산 일치)".

## 3. 지금 화면 구조에 대한 판단

기술적 분석의 질문은 "이 지수·종목의 차트는 지금 어떤 자리인가"다. 지금 화면(`ui/pages/charts.js:91-136`)은 지수 카드 → 반등 트랙 → 지수별 과거 하락 구간 → 대표 종목 카드 → 종목 표 → 종목 분석 슬롯 순이다.

1. 지수 카드의 '거래량' 줄이 지수마다 다른 판정 하나씩이다(S&P는 분배일, 나스닥은 FTD, 나머지는 없음 — `market-charts.js:79-94`). 같은 화면에서 지수끼리 비교할 수 없다. 카드마다 같은 칸(가격 자리: 일·주·월 선 사다리 / 거래량: 분배일·상승하락 거래량 비 / 상태 꼬리표: 돌파 실패·과매도 반등)으로 다시 짜는 것이 맞다. 방법 #2·#6·#7·#11이 여기로 모이고, 덧붙이는 것이 아니라 카드 한 장의 구조를 바꾸는 일이다.
2. 반등 트랙과 과거 하락 구간 표(`charts.js:104-111`)는 `market-story.js`가 소유한 시장 해석을 그대로 그린다. 시장과 매크로의 시장 상태가 같은 것을 보이면 한 정보를 두 화면이 소유하는 셈이다. 이 화면에는 '지수 낙폭이 과거 분포의 어디인가' 한 줄과 링크만 두고, #4(과매도 반등 분류)·#10(급락일 사건 표)는 차트 자리 판정이므로 지수 카드 안으로 넣는 쪽을 권한다. 반등 단계(시도/회복/실패)와 바닥 체크(`market-read.js:1001`)는 시장 상태 쪽에 남긴다.
3. 종목 분석 슬롯은 이미 상태·이유·체크리스트·렌즈·과거 돌파·시나리오·레벨 지도를 갖고 있어 방법을 더 붙일 자리가 아니다. 부족한 것은 맨 위 한 줄의 상태어 결정 규칙(#20)뿐이다. 오히려 렌즈 4개·체크리스트·생애 주기가 같은 사실(템플릿, 거래 마름, 50일선 확장)을 세 번 센다 — 한 번 계산한 사실 표를 셋이 읽도록 합치는 정리가 필요하다(`setup-coach.js:54-96`, `chart-strategies.js:59-128`, `chart-analysis.js:249-271`).
4. 셋업 사다리(`setup-board.js`)는 시장 폭·테마·스크리너 세 화면이 쓰는데, FTD 뒤 주도주 확인(#5)은 이 화면의 지수 판정과 이어져야 의미가 있다. 사다리 집계는 그대로 두고, 지수 카드의 FTD 칸이 사다리 카운트를 읽게 잇는다.
