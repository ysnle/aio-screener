# 구조·정책·규칙 자체의 품질 판단

이 문서는 구현 제안이다. 기존 소유자 결정도 이전 에이전트의 판단도 정답으로 전제하지 않는다. 근거는 본 폴더의 격리 실행/실브라우저 기록 및 이전 날짜별 감사다. 제품 구조를 바꾸거나 기능을 제거하지 않았다.

| 영역 | 현재 판단과 사용자 가치 | 작은 보완 / 재검토할 기준 |
|---|---|---|
| 제품 규모 | 가족·지인5명, 무료·단일 운영자에 정적 셸+ESM/공유 Worker는 현실적인 구조다. 서버 프레임워크 전면 교체의 우월성을 입증한 측정은 없다. | 법인·날짜·통화·결측 계약부터 고친다. 단순히 큰 파일/많은 모듈이라는 이유로 재작성하지 않는다. |
| 계층·책임 | domain/UI/producer 분할은 순수 계산의 반례 실행을 쉽게 했다. 동시에 core의 CIK 표와 각 UI의 FY substring은 정본을 중복한다. | issuer와 fiscal label을 공통 경계로 모으고 consumer의 동일성을 검증한다. 범용 추상화보다 반복된 실제 오류 클래스의 좁은 계약이 우선이다. |
| 상태·수명 | 새 inspector는 데스크톱의 근거 접근을 쉽게 하지만 이전 row 객체가 새 조건에 잔류한다. | 선택 symbol과 현재 실행 결과를 연결해 다시 도출한다. 모델/기준일이 바뀌면 표시 근거도 바뀌는지 행동으로 확인한다. |
| 숫자의 의미 | 계좌 β는 현금·환율 기준이 빠지고, 섹터는 채권을 포함한 분모를 주식 분모로 설명한다. | 값마다 통화·분모·기간·모집단·결측을 정하고 문구와 맞춘다. 더 많은 숫자를 붙이는 것보다 같은 숫자를 정확히 설명하는 것이 우선이다. |
| 재무 해석 | DuPont의 대수식은 맞아도 원인 문장의 방향이 반대가 될 수 있다. 역 DCF는 가정과 한계를 화면에 공개한다. | 상쇄/기여 방향을 분리한다. 공개된 가정 모델을 매매 판정으로 확대하지 않는다. 회계연도는 공시의 이름을 보존한다. |
| 통계·검증 | 최소 표본과 t 기준을 두는 의도는 타당하다. IC의 t가 수익률 차이의 유의성을 대신하지 못한다. | 무엇을 검정한 t인지 명시하고 그 시계열만 판단한다. 예측 검증 전 순위를 후보로 쓰는 기능은 유지할 수 있다. 표본12 또는 t2라는 문턱 자체가 최선의 추론을 보장하지 않는다. |
| 시나리오·일반 선택지 | 조건부 선택과 기회비용은 유용하다. 분기 개수로 최소 비용을 증명할 수는 없다(이전 INTERPRETATION). | 관측·조건·전달 경로·비용 가설·실증을 구별한다. 분기 개수는 개수로 말한다. 개인 보유에 대한 매매 지시로 바꾸지 않는다. |
| 최신성 | 각 출처 발표 주기를 따르고 실제 관측/공시일을 표시하는 방향은 타당하다. 현재 한국 수급의5일 입력도 stale=false인 후보는 실제 게시 주기 검증이 남는다. | 일률적인 시간/일수보다 다음 발표와 장일 캘린더로 판단한다. 없는 입력의0% 변환과 수집시각의 공시시각 대체를 막는다. |
| 화면 설계 | 상태 한 단어·명명된 축·계산 가정·태블릿 dialog의 Escape 복원은 확인했다. 휴대폰 첫 화면은 질문/상태 설명의 비중이 크다. | 결론과 핵심 추이·다음 확인을 우선 배치하고 상세 근거는 펼쳐 본다.3초 이해는 설계 목표이며 실측 없이 달성했다고 부르지 않는다. |
| 접근성 | 검색 blur는 실제 키보드 접근을 끊는다. 다른 dialog의 정상 동작으로 상쇄되지 않는다. | focus가 컴포넌트 밖으로 나가는지 판단한다. 자동 DOM 텍스트 존재를 실제 가시성/키보드 성공으로 대신하지 않는다. 전체 WCAG 인증은 별도 미검증이다. |
| 성능·크기 | ESM boot minified/gzip 예산은 실제 PASS했다. 전체 초기 다운로드·기기 paint는 미측정이다. SEC1MiB 제한의 여유는 작다. | 전송·boot·라우트 갱신을 실제 사용자 경로에서 나누어 측정한다. 임의 고정 예산이 데이터 갱신을 지속적으로 막는다면 수집/분할 설계를 재검토한다. |
| QA 체계 | 실제 경계 반례를 잡는 gate는 가치가 있다. cache dependency 누락, 최고 R 삭제 미검출, literal 정규식 범위는 확신을 과장시킨다. | gate 수/PASS 수 대신 어떤 반례를 차단하는지 본다. 자동 문서 검사와 의미 검토를 분리한다. read-only gate의 파일 쓰기 효과도 계약화한다. |
| 규칙·기록 | 과거 회귀를 보존하는 P/R/QA 기록은 유용하다. 모든 작은 변경에 더 많은 텍스트 pin/기록을 붙이면 유지 비용이 커진다. | 재발 가능한 오류 클래스와 실행 근거 중심으로 기록한다. 현재 max/개수만으로 규칙 보존을 보장하지 않는다. 실제로 변하지 않은 파일의 재검사를 반복하지 않는다. |
| 운영·배포 | producer를 Actions로 모으고 명시적 commit/push/deploy를 요구하는 경계는 실수 방지에 유효하다. | 순수 격리 함수 검증을 producer 실행으로 오해하지 않게 분리한다. 가족 도구에 공용 SaaS의 형식 인증을 출시 장애물로 요구할 이유는 없다. |
| 보안·비용·권리 | 비밀과 공유 예산 보호, 공개 저장소의 노출 인식, 공급자 조건 준수는 유지할 가치가 있다. | 요청 횟수는 청구 상한과 다르다. 로컬/격리 PASS로 실제 청구나 배포 Worker의 상태를 인증하지 않는다. 제공처별 실제 재사용 조건은 근거가 필요한 경우에 대조한다. |
| 학습·콘텐츠 | 폭넓은 교육 자료는 가족 사용자의 이해를 돕는다. 글 수·출처 링크가 모든 문장의 타당성을 증명하지 않는다. | 관례·조건부 경험칙·검증된 사실을 구별하고 반례/조건을 붙인다. 이번 소스 원장850개는 지식 본문·데이터셋 전수 의미 검토 수가 아니다. |

추가 전문 검토로 수익률 기간 창작·응답 매매 지시 경계·QA 실패 캐시를 우선순위에 올렸다. [공통 UI](./REMAINING-UI.md)의 원가손익→가짜30일 fallback은 ‘추정’ 경고만으로 정당화되지 않는다. [chat](./REMAINING-CHAT.md)의 일반 조건부 시나리오는 유지하되 명백한 지시를 부정절 때문에 면제해서는 안 된다. 보수적·강한 gate 자체도 정답은 아니다. [완료를 영구 거부하는 gate](./REMAINING-GOVERNANCE.md)는 증거가 있는 정상 상태로 가는 경로를 열어야 하고, [과거 성공으로 실패를 덮는 retry](./REMAINING-QA-RUNNER.md)는 실제 재실행을 요구해야 한다.

첫 리팩토링 묶음으로는 issuer 검증/수익률 기간·결측/응답 지시/실패 캐시 경계가 적절하다. 이후 FY 공통화/계좌 분모와 통화/부호 설명, inspector·검색 포커스와 QA fingerprint/규칙 집합을 보완한다. [SEC 수집 marker](./REMAINING-WORKFLOWS.md)는 단순 성공 종료와 결과 보존을 구별하고, [버전 도구](./REMAINING-WORKSPACE-TOOLS.md)는 같은 canonical 문법을 공유해야 한다. 레거시 전체 이전이나 프레임워크 전환은 그 뒤 실제 중복 책임과 측정 이득이 확인되는 구간별로 결정한다. 기능 폐지·통합은 제안으로만 남긴다.
