## 실제 설정 확인

- 사용자 설정의 기본 모델: `gpt-6-astra`, 추론 강도: `medium`. 유지했다.
- `[features.context_management] experimental_mode = true`: 이미 설정되어 있어 다시 쓰지 않았다. [공식 변경 기록](https://learn.chatgpt.com/docs/changelog)의 설정 이름과 대조했다.
- PATH의 실행 파일은 데스크톱 앱에 포함된 `codex.exe`이고, `codex --version`은 `0.144.1`을 반환했다. 가이드의 0.153.4 권장 버전과 다르다. 실행 중인 앱에 포함된 바이너리를 임의로 교체하거나 중복 CLI를 설치하지 않았다. 앱 업데이트 여부는 미해결이다.
- 연결 도구나 설치 스킬을 일괄 삭제·비활성화하지 않았다. 어떤 작업에 불필요한지는 이 요청만으로 전체 계정에 대해 결정할 수 없다.

## 승인 후 적용한 변경

1. **사전 읽기 범위:** AGENTS의 공통 3문서 읽기를 `CURRENT-STATE` 작업 시작 1회, `INDEX` 위치 탐색 시, `WORKFLOW-GOVERNANCE` QA·권한·워크플로 상세 필요 시로 변경. 변경 없는 기존 읽기는 재사용한다. 작업 경계의 git 확인과 content-hash 기준선은 유지한다.
2. **스킬 선택과 참조:** 키워드 일치만으로 전체 절차를 강제하지 않는다. 해당 작업에 도움이 되는 스킬의 진입점과 필요한 reference만 읽는다. 여섯 스킬에 중복된 공통 읽기 문구를 공유 계약 참조로 바꾼다.
3. **좁은 작업의 범위:** 단일 데이터 갱신은 해당 범주만 점검하고 전체 freshness audit에는 기존 22범주를 모두 적용한다. 지식 린트도 targeted/full 범위를 구분한다. 전체 감사 요청의 범위를 줄이지 않는다.
4. **자율 진행과 완료:** 요청을 구현·실행·검증·관련 실패 수정까지 수행한다. 이미 승인된 로컬 수정·생성·격리 테스트에는 중복 확인을 요구하지 않는다. commit, push, deploy는 여전히 각각 명시적 사용자 요청이 필요하다.
5. **병렬 위임:** 도움이 되는 큰 작업에서 독립 조사·리뷰만 명확한 소유권으로 분리한다. 작은 작업과 동일 조사는 중복 위임하지 않고 주 담당자가 결과를 통합 검증한다.
6. **검증 재사용:** 낮은 영향의 가역적 변경에는 구현을 복제한 테스트를 추가하지 않는다. 통과한 검사는 새 입력 변경·실패·미해결 위험이 있을 때만 재실행한다. 필수 기존 게이트·예산·판정 기준은 삭제하거나 완화하지 않는다.

동기화 대상은 `AGENTS.md`, `CLAUDE.md`, `_context/CLAUDE.md`, `_context/INDEX.md`, `_context/WORKFLOW-GOVERNANCE.md`, `.claude/skills`의 원본 지침, 읽기 정책 생성기다. `.agents/skills`와 현재 상태·카탈로그는 공식 생성기로 갱신한다. 사전 읽기 바이트 집계는 실제 필수 문서만 측정하도록 맞추고, 관련 workspace/skill 계약으로 검증한다.

## 유지되는 경계와 위험

기존 사용자 변경 보존, 생성물 직접 편집 금지, 커밋·push·배포의 개별 승인, 실제 증거 수준 구분, 데이터 출처·시각·결측 경계, 필수 QA는 유지한다. 변경의 위험은 미래 작업에서 문서 읽기와 작업 범위를 에이전트 판단에 더 맡기게 되는 점이다. 위 변경은 사용자 승인 후 적용했으며 추가 승인을 기다리는 상태가 아니다.
