## 제안 1 — 정보 구조 19개 → 8개 화면

| 새 화면 | 통합 대상 | 이유 |
|---|---|---|
| 오늘 | 대시보드 + 브리핑 + 시장 뉴스 | 셋 다 "오늘 시장"을 다르게 요약한다. 브리핑은 이미 5.1화면이다 |
| 시장 상태 | 시장 환경 + 시장 폭 + 투자 심리 | 점수의 구성 요소(변동성·폭·심리)를 한 화면에서 근거와 함께 보여 준다 |

## 제안 2 — 정직함은 유지하고 표현은 계층화

- 카드마다 상태 칩 하나(최신 / 지연 / 참고 / 없음)를 두고, 세부 근거는 펼치기나 툴팁으로 보여 준다.
- 면책은 전역 고지 하나로 모은다. 브리핑 33회, 아틀라스 20회, 심리 17회의 반복 문구는 줄인다.
- 원천이 아예 없는 위젯은 상시 "—" 대신 숨긴다. MOVE, SKEW, VVIX, 섹터 ETF 등락처럼 "현재 원천 미수신"이 고정인 항목이 해당한다.
- 개발자용 문자열은 접는다. 스크리너의 `run-38743a5e`, `mic_missing`, preset hash, "모델 검증 BLOCKED" 같은 표기가 해당한다.

## 제안 3 — 근거 없는 수치·장식 제거

- 점수에서 만든 의사 등급은 뺀다. 시그널의 "TPR C", "M7 0/0", 테마의 "참고 조합 38/100"이 해당한다. 점수 자체는 "매매 지표 아님"인데 등급이 다시 판정처럼 보인다.
- 테마의 정적 교과서 "섹터 순환 지도"(바닥→강세장→피크)는 배우기로 옮긴다.
- 개발자 진단 패널은 일반 화면에서 이미 숨겨져 있다. 유지하되 점수 표기는 P1369대로 실제 측정 의미에 맞췄다.

## 제안 4 — 데이터 주기 정리 (정적화 질문에 대한 판단)

- **13F(대가 포트폴리오):** 공시는 분기마다 나오고, 분기 종료 후 45일 안에 제출된다. 브라우저 입장에서는 이미 정적 JSON이다. 낭비는 생산기가 매일 시각만 바꿔 다시 쓴 데 있었고, P1370으로 해결했다. JS 코드에 하드코딩하면 번들이 커지고 출처·기준일 관리가 어려워진다. 정적 JSON 파일 + 분기 공시 시즌에만 갱신하는 방식이 더 쉽고 정확하다. 매일 돌리는 13D/G 조회는 가족용으로는 필요성이 낮아 끄는 것을 제안한다.
- **지식베이스(원리·지식 지도·용어):** 이미 변경 시에만 빌드되는 정적 파일이다. 손으로(또는 AI 도움으로) 고치는 정적 콘텐츠로 확정하고, 생성 파이프라인은 검증 용도로만 남긴다.
- **뉴스 번역:** 지금은 방문자 브라우저마다 같은 기사를 따로 번역한다. Actions에서 주기마다 한 번 번역해 발행하는 것이 구조적으로 맞다. 비용 결정과 묶여 보류 중이다.
- **git 이력:** 이미 쌓인 13F 사본(pack 619MB)은 이력 재작성이 필요하다. 되돌릴 수 없는 작업이라 별도 결정 사항이다.
