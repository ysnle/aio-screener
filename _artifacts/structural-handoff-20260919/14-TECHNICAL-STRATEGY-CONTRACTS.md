# 차트 관측에서 행동 전략까지의 계약

## T04 — 부족한 주봉 이력을 하락으로 해석

확정: `js/aio-core.js`의 `_calcWeeklyContext`(20642–20678)는 일봉을 최신 기준 5개씩 묶고 SMA20/50의 기간을 각각 `min(요구 기간, 실제 개수)`로 줄인다. 20개 이하 묶음에서는 두 평균이 같고, 동률을 bearish로 반환한다. `analyzeTickerDeep`은 60개 일봉부터 진입할 수 있고 차트 설명은 이를 주봉 상승/하락과 SMA20/50으로 표시한다(`js/aio-ui.js:5749`, `5954`).

실제 함수를 분리 실행한 [합성 증거](5601-weekly.json): 매일 1씩 오르는 60개 봉에서 12개 묶음, SMA20=SMA50=131.5, bearish. 100개 봉에서도 bearish. 250개 봉에서는 bullish. 상승 입력이 반드시 강세 신호여야 한다는 주장이 아니다. **요구한 50개 관측이 없는데 50기간 평균인 것처럼 비교하는 것**이 결함이다. 실제 브라우저에 해당 합성 이력을 주입한 검증은 하지 않았다.

설계: 기간을 자동 축소하지 않는다. SMA20과 SMA50의 값·준비 상태를 독립적으로 반환하고 추세 비교는 양쪽 준비 후 수행한다. 동률은 neutral로 정의한다. 5거래일 묶음은 거래소 달력 주봉과 같지 않으므로, 단기적으로 이름을 정확하게 바꾸고 장기적으로 거래소·시간대·주 마감·진행 중 봉을 포함한 calendar aggregation을 소유 모듈 하나에 둔다. 휴일과 부분 주의 처리 방침을 기록한다.

사용자 문구: “장기 주봉 추세는 아직 계산할 수 없습니다. 50주가 필요하며 현재 12개 5거래일 묶음이 있습니다.” 관측 가능한 최근 상승과 계산 불가능한 장기 추세를 동시에 보여준다. 빨간 하락 배지로 대체하지 않는다.

인수: 12/19/20/49/50 관측 경계, 동률, 휴일 주, 최신 진행 중 주, 중간 결측. 필요 기간을 바꿔도 동일한 이름을 유지하는 계산을 금지한다. 최종 UI와 AI 모두 같은 준비 상태를 소비한다.

## T05 — VCP라는 이름 아래 서로 다른 모델

정적 확인: snapshot `_calcVCP`(core20411)는 최소 60봉, Stage2, 최대 65봉 기반과 최근 25봉 pivot, RVOL 1.4를 사용한다. 차트 `_calcVcpQuality` 및 `_buildMinerviniTechnicalEngine`(ui5606–5657)은 최소 70봉, 60/30/15 범위 수축, 거래량10/50, pivot20 및 다른 내부 breakout 기준을 사용한다. 차트는 두 번째 점수를 표시한다. 모든 내부 breakout boolean이 사용자에게 표시된다는 뜻은 아니다.

두 목적이 다르면 두 모델을 유지할 수 있다. 다만 공통 이름만으로 같은 결과라는 인상을 주지 않도록 `modelId/version/purpose/inputWindow/adjustment/pivotDefinition`을 결과 계약에 넣는다. 공통 관측 피처는 한 계산 모듈에서 공급하고, 패턴 탐지와 진입 준비도는 별도 모델로 선언한다. 의도한 차이가 아니면 대표 모델을 결정하고 기존 모델을 명시적으로 폐기한다.

사용자는 “수축 관측 → 추세 조건 → 돌파 확인 여부 → 유동성/위험 조건”을 순서대로 펼칠 수 있어야 한다. 차트의 해당 기간과 기준선을 선택하면 설명 행이 강조된다. 점수만으로 패턴 확정·매수 적합성이 성립하지 않는다. 동일 fixture에서 두 모델의 차이가 설명 가능한지 인수한다.

## T06 — 규칙 점수를 매매 지시로 전환하는 경계

`_assessEntryQuality`(ui5353–5414)는 MA 정렬, EMA 거리, 거래량, RSI에 정수 점수를 더해 등급을 만든다. 기술 엔진은 이를 다른 점수와 가중 합산하고 “기관급 후보” 등으로 표현한다. `calcSellPressure`(core21133)는 ATR 거리·RSI 등의 누적 규칙을 action 코드로, `calcExitPlan`(21183)은 축소 비율과 stop/thesis 선으로 전환한다. 예를 들어 ATR 거리 ≥6은 중첩 조건 12+12+20점을, RSI ≥85는 8+10점을 더한다. 중첩 자체가 오류라고 단정하지 않는다. 의도한 누적 가중인지 정의와 검증이 필요하다. exit plan의 regime 인자는 반환되지만 계산에 쓰이지 않는다.

현재 검토한 점수는 경험 규칙이며 수익 확률·기관 검증 성능을 입증한 자료는 확인하지 않았다. 따라서 ‘기관급 후보’는 이 점수의 근거로 정당화되지 않는 표현이다. 정의와 별도 검증 근거가 마련되기 전에는 ‘기술 규칙 충족 후보’처럼 범위가 명확한 표현으로 바꾸거나 해당 라벨을 제공하지 않는 것을 인수조건으로 둔다. 목표 계약은 세 층이다.

1. **관측 결과**: 가격/거래량/지표, 기준일, 조정 방식, 준비 상태와 기여 내역.
2. **전략 해석**: 전략 이름·버전·기간·가정·무효화 조건. 상관된 피처의 중복 기여와 민감도 공개.
3. **사용자 적용**: 보유 여부, 시간 지평, 유동성, 비용, 허용 손실 등의 조건을 충족한 경우에만 조건부 행동 시나리오. 정보가 없으면 관찰 또는 조건 비교로 남긴다.

“25% 축소”를 단독 결론으로 보여주지 말고 “이 규칙은 이격 과열에 반응합니다 → 보유 전략이 해당할 때의 축소 시나리오 → 적용되지 않는 경우 → 다음 재확인 조건”을 같은 화면에 연결한다. 손절 참고선과 실제 주문·체결 보장은 구분한다. 사용자가 임계값 하나를 바꾸면 바뀐 관측·점수·시나리오를 비교할 수 있으나 새로운 계산은 가정 변경으로 명확히 표시한다.

구현 순서: 현행 공식/출력 fixture 고정 → 관측과 정책 결과 분리 → 설명 모델 통합 → 전략별 검증. 성능 주장은 시점 가용성·기업행동·비용·표본 외 검증을 포함한 별도 연구가 끝난 뒤 허용한다. 이 문서가 특정 임계값의 투자 적합성을 인증하지 않는다.

## 추가 조사 경계
