## B01 — 각 화면의 문구가 아니라 의미 소유권을 통합한다

**확인된 사용자 문제:** 총점 보류와 부분 0점, 값과 '미수신', 계산과 차트 대기가 동시에 나타난다. 전부 동일 원인이라고 단정하지 않는다. 일부는 참고값과 계산 적격성 차이이고 일부는 독립 writer/수신 경로 차이일 수 있다. 그러나 사용자가 이유를 이해할 수 없는 현재 화면의 문제는 직접 관측했다.

**설계 선택:** 모든 값을 단일 전역 객체에 억지로 합치지 않는다. 19의 observation→result→claim 연결 계약 위에 **같은 의미 단위의 표현 모델**을 두고 UI/AI/차트가 이를 소비한다. 출처·기준일이 다른 사실은 별도 observation을 유지한다.

표현 모델 최소 필드:

```text
metricKey + instrumentRef + populationRef + period + unit
observationId / resultId / sourceRevision / modelVersion
availability: not_requested | loading | observed | unavailable | failed
eligibility: eligible | reference_only | stale | incompatible | insufficient
value: finite number | null
reasonCodes[] / operandRefs[] / observedAt / availableAt
scope: market | selected_instrument | selected_universe | portfolio
```

availability와 eligibility는 별도 축이다. 값이 존재하지만 참고 전용이면 '9/18 참고 RSI64.3 · 현재 판정 제외: 사유'로 표현한다. 이를 '데이터 없음'으로 바꾸거나 반대로 참고값을 자동 승격하지 않는다. 유효0만0으로 표시하며 null의 색·점수·문장 생성을 차단한다.

**사용자 흐름:** 한 문장 결론→사용 가능한 근거/부족한 근거→계산·비교 기준→다음 확인 대상. 최초 화면에는 사용자 언어를 쓰고 source ID·schema·producer는 상세 근거 패널로 이동한다. 일반 사용자가 producer 용어를 해석해야 하는 구조를 없앤다.

**경계별 owner:** producer는 사실/시간/단위, normalizer는 식별·결측, domain은 적격성/계산, presentation owner는 값·배지·설명 원자적 생성, UI는 배치만 담당. AI는 같은 result/claim ID를 인용하며 독립 점수와 방향을 재계산하지 않는다. 로딩 종료·실패·재시도도 같은 owner가 관리한다.

## B02 — 기술 분석은 선택 종목의 단일 실행 결과로 재설계한다

QQQ 버튼을 누르면 상세 RSI65.7·Stage2·기관급후보78/100·진입B가 생성되지만 상단 RSI58.4/MACD−0.2와 차트대기가 남았다. 상단이 시장 지표라면 **SPY 시장 참고**라고 표시하고, 선택 종목 패널이면 QQQ 결과를 함께 갱신해야 한다. 어느 쪽이든 scope가 빠진 숫자를 방치하지 않는다. '확도60%'는 검증된 확률인지 휴리스틱인지 구분해야 하며 현재 증거로 확률 의미를 인증하지 않는다.

재설계 실행 단위는 `(instrument, timeframe, adjustmentPolicy, seriesRevision, modelVersion, requestId)`이다. canonical series를 검증한 후 지표·패턴·해석·차트 좌표를 한 result로 발행한다. 늦게 끝난 이전 종목 요청은 최신 requestId에 쓰지 못한다. 차트 렌더 실패는 '시세 없음'이 아니라 '관측자료 있음·차트 표시 실패'로 남긴다. 캔들 패턴·Stage·VCP·Volume Profile의 원시 이력과 조정 기준을 공유하되 각 모델의 최소 표본은 독립 관리한다.

**추가 실제 오류:** 재방문 시 양쪽 콘솔에 `updatePatternSignals`, `js/aio-macro-tech.js:552`의 null.toFixed 예외가 기록됐다(UTC23:39:34/38). 로컬 코드는 `if (hygPrice < 73)` 뒤 `hygPrice.toFixed(1)`를 호출한다. null이 숫자 비교에서0처럼 취급되는 경로를 막아야 한다. 이 예외가 차트 공백의 유일한 원인이라는 인과는 아직 입증하지 않았다.

한 줄 가드만으로 완료하지 않는다. 결측이 금융 위기 조건을 만족하지 못하도록 각 rule operand에 finite·source·time 검증을 적용하고, 한 분석의 실패가 나머지 렌더를 중단하지 않게 결과별 오류 경계를 둔다. HYG 가격 수준을 신용스프레드 자체로 부르는 금융 의미도 별도 폐기/재설계 대상이다. 기관급·진입등급 같은 명칭은 검증 수준과 전략 적용 조건을 갖춘 뒤 노출한다(14와 연결).

## B03 — 시간창·커버리지·상태를 데이터에서 계산한다

뉴스의 cacheFetchedAt은 publishedAt·observedWindow와 다르다. 당일 창 밖 기사만 남았다면 '오늘8건'이 아니라 '오늘 자료 미확보 · 이전 수집분8건'으로 표시한다. 수집이 성공해도 내용이 오래됐으면 CURRENT로 승격하지 않는다. headline-only는 원문 확인 없이 인과·전망·행동을 사실 설명에 합치지 않는다. 경제 일정0건은 수집 완전성이 증명된 해당 window에만 '없음'이며, 실패/미연결은 '확인 불가'다.

브리핑의 F&G 부재→극단 공포 문장, signal의 이벤트없음→통과는 **결측이 방향·행동으로 변하는 경로**로 우선 추적한다. 스케줄 실행, 자료 도착, 정합성 통과, 브라우저 소비를 별도 운영 상태로 두는17을 적용한다. 정적 refresh는 재현 가능한 사실을 보강하는 정상 생산 경로이고, websearch는18의 후보 검증 경로다. 검색 결과를 곧바로0건 여부·현재값·매매 해석에 넣는 임시 폴백은 채택하지 않는다.

## B04 — 스크리너의 사용자 결과를 '조회·적격·조건'으로 분리한다

현 화면은 AAPL검색 결과1개인데873부족을 실행 결과로 강조한다. 전역 coverage는 별도 보조 정보로 두고, 실행 funnel은 `조회 대상1 → 계산 적격0 → 통과0 / 판정불가1`로 설명한다. 부적격 이유는 필드 없음, 오래됨, 출처 미검증, 모델 미승인 등으로 나눈다. 참고3M12.9%를 보면서 price.ret3m미수신을 읽는 충돌을 없애야 한다.

정식 실행은 snapshot/정의/model/universe revision을 보존한다. 현재 보관 기능이 설명하듯 '입력 보관'만 가능하면 결과 재현을 약속하지 않는다. 짧게 잘린 `screener-snapshot-` 표시 대신 식별 가능한 실행명과 시각, 상세 immutable ID를 제공한다. 왜 통과했는지만큼 왜 제외·보류됐는지를 동일 계약으로 생성한다. 전체적으로 거래용 승격이 차단된 현재 상태를 강제로 풀어 결과 숫자를 채우는 수정은 인수가 아니다.

## 단계별 작업 경계와 인수

1. **B01 파일럿:** breadth 한 지표와 signal 한 구성요소를 선택해 기존 writer를 열거하고 표현 owner를 하나로 만든다. observed/reference/null/failed/valid-zero 5상태를 값·배지·문장·AI 근거까지 같은 fixture로 대조한다.
2. **B02 세로 경로:** SPY→QQQ→AAPL 요청 역전, 부분251봉, 히스토리 실패, 렌더실패를 분리 재현한다. 차트·지표·해석이 instrument/timeframe/revision에 동의하고 null에서 예외·위기 문장이 없어야 한다.
3. **B03 운영 연결:** 오늘 창에0건·과거8건·수집 실패를 서로 다른 fixture로 둔다. 캘린더0건은 완전수집 근거를 요구한다. 운영SLO는 도착 예정과 실제 소비를 비교한다.
4. **B04 실행 계약:** 유니버스873/검색1/적격0을 혼동하지 않고, 참고값의 부적격 사유를 Why와 표에서 같게 표시한다. 새 실행과 복원 실행을 독립 검증한다.

이 순서의 이유는 외관보다 잘못된 판단 생성과 사용자 오해를 먼저 줄이기 위해서다. 통합 전 old/new 결과를 shadow 비교하고 feature flag는 owner 단위로 전환한다. 실패 시 마지막 호환 결과 묶음으로 rollback하되 새 데이터를 구형 계산에 섞지 않는다. 기존 writer 삭제는 소비자 비교 통과 뒤 진행한다. 실제 구현은 별도 에이전트가 수행하며 이 문서는 코드 수정이 아니다.
