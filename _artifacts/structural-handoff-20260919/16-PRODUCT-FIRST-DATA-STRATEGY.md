# 제품 목적부터 다시 설계하는 데이터 전략

2026-09-21 · Astra 설계. v56.01 현행 구조는 분석 대상이지 유지해야 할 제약이 아니다. 이 문서는 실제 제품 설정을 바꾸지 않는 구현 핸드오프다. 스킬을 사용하지 않았다.

## 전수 검수 완료 여부

아직 아니다. 라우트 순회, 함수 표본, 합성 반증, 계약 게이트 통과는 각각 다른 증거다. 기존 `architecture/product-charter.json`의 영역별 AUDITED 표시는 이 감사의 전수 의미 검수 완료 증거로 채택하지 않는다. 선언의 존재와 실제 검증 범위를 구분한다. 기존 헌장의 점수도 평가 표본·루브릭 없는 정량 측정값으로 사용하지 않는다.

전체 범위를 빠뜨리지 않도록 아래 목록을 상위 범위로 유지한다. 상세 상태는 FUNCTION-REVIEW와 각 패키지를 따른다.

| 영역 | 현재 증거 수준 | 남은 핵심 검수 |
|---|---|---|
| 제품 목적·대상 사용자·성과 | 기존 헌장과 실제 동선 대조, 재설계 제안 | 실제 사용자 과업 성공과 이해도 |
| 수집·정규화·시점·단위·식별 | 핵심 경로 표본 및 반증 | 모든 공급자/필드, 기업행동, revision |
| 자동화·발행·분배·감시 | 소스 추적 및 운영집계 합성 반증 | 실제 장기 이력·복구·배포 수렴 |
| 팩터·순위·시장 모델·백테스트 | 주요 수식 표본 및 반증 | 전체 함수, 표본 외 성능·민감도 |
| 차트·기술 기법·행동 전략 | 주봉/VCP/일부 진입·축소 규칙 | 옵션·divergence·volume profile 등 |
| 포트폴리오·성과·개인 상태 | 저장/통화/빈 상태/일부 계산 | 회계·현금흐름·위험·복구 전수 |
| AI 검색·추론·정책·출처 | 정적 및 합성 공개 단계 | 실제 응답 품질·동시성·주장 원문 일치 |
| 콘텐츠·교육·기관 공시 | 표본 생성/범위/표시 확인 | 전체 내용의 금융 의미·학습 효과 |
| 연결 동선·접근성·성능 | 라우트 및 선택 동선 브라우저 표본 | 모든 상태·키보드·보조공학·실측 예산 |
| 보안·프라이버시·운영 비용·권리 | 일부 경계만 확인 | 위협 모델·전체 전송/보존·사용 권한 |
| 테스트·거버넌스·migration | 계약 검사와 일부 의미 fixture | 게이트 사각지대·writer 폐기·rollback |

## 무엇을 위해 만드는가

기관/펀드급이라는 목표는 화면의 정보량이나 매매 문구 강도로 측정할 수 없다. 제안하는 기준은 **같은 입력과 방법으로 결과를 재현하고, 비교 가능한 집단을 정의하고, 근거의 시점·한계와 판단 과정을 검토할 수 있는 연구 품질**이다. 실제 기관 운용 서비스에 필요한 계약·데이터·운영 능력의 보유는 별도 검증한다.

핵심 과업은 “시장 맥락 파악 → 조건으로 후보 축소 → 대안 비교 → 반증과 위험 검토 → 논지 기록 → 결과 복기”다. 모든 기능은 이 과업에 기여하는지 평가한다. 기존 기능이라고 유지하지 않는다. 동일 질문에 다른 숫자를 만드는 중복 모델은 통합하거나 용도를 분리한다. 입력이 없어 검증할 수 없는 기능은 참고/실험으로 내리거나 제거한다. 브라우저 대량 수집, 전역 상태, 정적 배포 결합 역시 대체 가능하다.

다만 근거 없이 전면 재작성부터 택하지 않는다. 제품 계약을 먼저 정하고, 현재 구현이 계약을 충족하면 재사용하며 충족하지 못하는 소유권·저장·발행 경계를 교체한다. 파일·프레임워크 보존은 목표가 아니다.

## 정적 Data refresh와 Websearch는 어디에 맞는가

여기서 Data refresh는 갱신 파이프라인을 뜻하며 스킬 실행 지시가 아니다.

| 요구 데이터 | 주 공급 방식 | 정적 갱신/검색의 역할 | 해결되지 않는 조건 |
|---|---|---|---|
| 기업 식별·분류·거래소·회계 정의 | 검증된 reference registry | 정기 refresh 및 공식 문서 검색으로 보강 | 동일 이름의 다른 종목·유효기간·출처 충돌 |
| 일봉·재무 공시·경제 관측 | 구조화된 공급자/공식 API + 이력 저장 | 주기/이벤트별 refresh 후 검증 발행 | 분할/배당 조정, 보고기간, 정정, availableAt |
| 대규모 스크리너 비교 | 동일 기준의 canonical dataset | 불변 정적 projection은 적합한 전달 방식 | 일부만 검색 보충하면 발생하는 선택 편향·비교 불균형 |
| 소수 기업의 특수 KPI·사건 | 공식 IR/공시 원문을 검색·추출 | 검색으로 후보 evidence를 확보하고 필드 계약 검증 | 검색 snippet만의 숫자, 문맥·단위·기간 불명 |
| 뉴스·원인 해석·연구 질문 | 검색 + 원문 + 해석 구분 | 질문별 맥락과 새 사건 보강 | 상관관계가 인과 증거로 바뀌지는 않음 |
| 장중 가격·호가·옵션 표면 | 요구 지연을 충족하는 공급 계약 | 정적 자료는 시점 참고, 검색은 자료 위치 탐색 | 연속성·지연·권리·동일 시각 표면이 없음 |
| 과거 시점 백테스트 | 당시 가용 데이터와 universe 보존 | 공식 과거 문서로 일부 복원 가능 | 오늘 찾은 현재 값으로 과거 정보집합 복원 불가 |

웹검색으로 값을 찾는 것은 가능하다. 그러나 “검색했다”는 사실은 값의 자격이 아니다. 원문을 확인하고 entity/metric/value/unit/period/availableAt/source/추출 근거를 묶어 후보 저장소에 넣는다. 검증된 값만 해당 데이터셋에 승격한다. 출처 간 충돌은 마지막 값으로 덮지 말고 미해결 상태로 보존한다. 원문을 확보할 수 없으면 발견한 링크만 남긴다.

공식 API가 있다면 대량 데이터는 API가 기본 경로다. 예를 들어 SEC는 구조화 API와 bulk 자료를 제공한다. 검색은 누락 사유 조사와 API가 포괄하지 않는 개별 문서의 보완에 유용하다. [SEC 공식 API 설명](https://www.sec.gov/search-filings/edgar-application-programming-interfaces).

## 데이터 요구사항을 먼저 정의

각 기능마다 `decisionQuestion`, 비교 모집단, 단위/통화, 기간/시점, 필요한 granularity, 허용 지연, 완전성, 조정 방식, 가용 출처, 허용 용도, 실패 행동을 먼저 작성한다. 그다음 required/optional 입력을 나누고 미충족 기능의 표현 또는 제공 여부를 결정한다. 모든 데이터에 같은 TTL과 CURRENT를 붙이지 않는다.

“모든 빈칸 채우기”보다 “이 질문에 필요한 입력을 충분히 확보했는가”를 기준으로 한다. 검색 결과의 특정 기업만 quality 팩터에 편입한다면 비교 집단과 편입 조건을 다시 계산해야 한다. 데이터가 없는 종목을 나쁜 기업으로 판단하지 않는다.

## 목표 구조 및 대체 조건

```text
기능별 데이터 요구 계약
  → 출처 adapter / 정기·사건·수동 보강 job
  → 원본과 수집 receipt 보존
  → 정규화·식별·시점·단위 검증
  → 후보 격리 / 충돌 해결 / canonical revision
  → 같은 revision으로 계산·설명·projection 생성
  → manifest 검증 및 원자적 공개
  → UI · 차트 · AI가 동일 결과 소비
  → 과업 성공·데이터 지연·실패·복구 측정
```

검색은 adapter 중 하나이고 AI는 검증된 evidence의 소비자다. AI 문장이나 검색 결과를 숫자 정본으로 되돌려 쓰는 무검증 순환을 금지한다. 정기 갱신이 완료되면 관련 계산·화면·검색 evidence를 dependency 기준으로 무효화한다.

소규모 저빈도 projection은 정적으로 유지할 수 있다. 갱신마다 코드 배포를 요구해 데이터 지연·경합을 만들거나 이력 보존/독립 rollback이 어려우면 데이터 publication을 별도 불변 object store와 manifest로 분리한다. 장중 지연 목표가 scheduler 능력을 초과하면 queue 기반 scheduler와 관측 가능한 worker로 옮긴다. 비용·지연·표본 크기를 측정해 선택하고 특정 플랫폼을 먼저 확정하지 않는다.

사용자에게 내부 job 이름을 보여주는 대신 “이번 비교는 9/18 종가와 가용 공시를 사용합니다. 12개 종목은 재무 기간이 맞지 않아 제외했습니다. 최신 사건은 별도 참고입니다.”처럼 실제 판단에 필요한 범위와 이유를 설명한다.
