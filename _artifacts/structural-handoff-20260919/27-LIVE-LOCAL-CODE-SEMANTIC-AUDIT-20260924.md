## 3. 발견 원장 — 재현·원인·개편 인수

### LC-01 · P1 · 기술 분석에서 선택 종목과 다른 심볼의 Stage를 무표기 병치

- **증거 `B+I+C`**: 라이브 `#technical`에서 QQQ를 누른 뒤 안정 화면의 종합 판정은 `QQQ는 천장 형성 중`, `2026-09-22 최근 일봉 종가 $747.46 (+0.81%)`였다. 바로 아래 심볼 없는 Weinstein 카드는 `1 바닥 형성 — 현재`, `2026-09-22 · 250거래일 · 종가 773.38`을 표시했다. [aio-ui.js](../../js/aio-ui.js)의 선택 티커 `analyzeTickerDeep()`(약 5725~6045행)과 [aio-macro-tech.js](../../js/aio-macro-tech.js)의 Stage 갱신(약 145~204행)은 서로 다른 로더다. 후자는 선택 티커를 받지 않고 `SPY` 일봉을 가져온다. 따라서 **QQQ의 종가가 두 개라고 단정하지 않는다**. 실제 결함은 QQQ 분석 맥락 안에 SPY Stage를 심볼 없이 배치한 것이다.
- **영향**: 사용자는 SPY 1단계를 QQQ의 Stage로 읽을 수 있고, 종합 판정과 같은 종목·세션으로 해석하게 된다.
- **개편 계약**: 종목·조정 기준(raw/adjusted)·거래소 세션·OHLCV 샘플 ID·관측 가능 시각을 포함한 하나의 `technicalAnalysisInput`을 생성하고, 종합 판정·차트·지지선·Weinstein·멀티타임프레임이 같은 입력 ID를 소비하게 한다. Stage가 의도적으로 SPY 전용 시장 참고라면 카드 제목·범위를 `SPY 시장 Stage`로 표시하고 선택 티커 분석과 시각적으로 분리한다.
- **인수**: SPY/QQQ/개별 티커 전환·재방문·비동기 완료 뒤 모든 카드의 symbol, session, close, adjustment basis, sample hash가 명시된다. 같은 분석으로 묶인 카드의 입력 ID가 불일치하면 결합 판정을 보류한다. 로컬에서 데이터가 미수신인 것만으로 해결 판정하지 않는다.

### LC-02 · P2 · 스윙 체크리스트가 미확인을 실패로 요약

- **증거 `B+C`**: 라이브 `#signal`은 `2/5 조건 미충족 다수`라고 썼지만 VIX/경제 일정 2개는 통과, 시장건강/섹터 폭/연속 상승 3개는 `대기`, 명시적 미충족 0개였다. [aio-pages.js](../../js/aio-pages.js)의 `updateEntryChecklist()`는 통과 수만 세고 `passed<3`이면 이 문구를 출력한다(약 671~766행). 종합 시장 점수 자체는 판정 보류였다.
- **추가 의미 경계**: 같은 함수의 `연속 상승 주의`는 연속된 일봉의 streak가 아니라 SPY 당일 등락률 하나로 판단한다. 이 이름을 유지하려면 여러 세션의 연속 조건이 필요하며, 단일 일간 과열 검사라면 이름을 그에 맞게 바꿔야 한다.
- **개편 계약**: 각 조건을 `pass/fail/unknown`으로 계산하고 합계 `통과 2 · 미충족 0 · 미확인 3 / 5`를 출력한다. `unknown`을 fail로 요약하거나 빨간색 실패 서술로 전환하지 않는다. 매매 가능성 문구와 분리한다.
- **인수**: 0~5개 입력의 모든 삼중 상태 조합에서 합계가 원소 상태와 일치하고, `unknown>0`이면 확정적 실패/통과 표현이 나오지 않는 경계 사례를 검증한다.

### LC-03 · P2 · 설명서 빠른 이동 대상 부재

- **증거 `B+I+C`**: [index.html](../../index.html)의 빠른 이동 키 `guide-valuechain`, `guide-glossary`, `guide-faq`, `guide-api`에 대응하는 DOM ID가 없다(약 12453행). [guide.js](../../src/ui/pages/guide.js)는 ID를 찾지 못하면 접두어를 제거한 검색으로 대체한다(약 107행). 라이브에서 밸류체인은 `“valuechain” 검색 결과가 없습니다`, 용어사전은 `“glossary” 검색 결과가 없습니다`; FAQ·API 설정은 검색 결과 목록을 보여주었다.
- **개편 계약**: 빠른 이동은 실제 섹션 ID·초점·스크롤이 일치해야 한다. 검색은 별도 기능으로 유지하고 존재하지 않는 앵커를 조용히 검색으로 바꾸지 않는다. 섹션이 없는 항목은 제거하거나 정본 문서로 명시적으로 라우팅한다.
- **인수**: 모든 빠른 이동 버튼에 실제 대상이 있고, 클릭 후 해당 섹션이 열리고 초점이 이동하며 제목이 화면에 보이는지 브라우저에서 확인한다.

### LC-04 · P2 · SEC Frames의 비교 모집단을 섹터로 오표기

- **증거 `B+C`**: 라이브 AAPL 기업 분석의 섹션 제목은 `SEC XBRL 섹터 백분위`지만 바로 아래 설명은 `전 US-GAAP 보고 기업 대비`다. [aio-chat.js](../../js/aio-chat.js)의 SEC Frames 조회는 업종 미조정 모집단이며(약 7932~7969행), [aio-ui.js](../../js/aio-ui.js)가 이 제목을 표시한다(약 3011~3053행). `Rank 4911/4914 · 상위 0.1%`는 오름차순 순위 산술상 일관되지만 순위 방향 설명이 부족하다.
- **개편 계약**: 헤더를 전체 보고기업 비교로 고치고, 업종·기간·metric·표본 수·동률 처리·순위 방향을 한 카드에 묶는다. 섹터 비교가 필요하면 실제 섹터 분모를 계산한 별도 모델과 라벨로 분리한다.
- **인수**: 표시된 모집단·퍼센타일·rank가 동일한 Frames 표본과 같은 회계 기간을 가리키며, 순위 해석을 사용자가 역으로 읽지 않도록 표시한다.

- **개편 계약·인수**: 캔들·이동평균이 제품 요구라면 OHLCV 단일 입력으로 실제 봉/MA를 그리며 범례·값·컷을 검증한다. 종가 선을 유지한다면 제목·범례를 실제 표현으로 바꾸고 캔들/MA 약속을 제거한다. 입력 부재 시에는 그림·범례 모두 보류 상태를 일치시킨다.

## 4. 잘 보류한 부분과 검증하지 못한 부분

- **확인된 보류 처리**: 시장 점수·시장 breadth·VIX 기간구조·테마 상세·가격 없는 포트폴리오·스크리너 모델 검증은 결측/미확인을 대체값으로 채우지 않았다. AAPL의 SEC FY 기준일·제출일·PIT 건수와 Yahoo 미수신에 따른 PE/시총 N/A는 현재 코드 계약에 맞았다. Berkshire 13F 전체 보유는 SEC 보고분기, 전체 89행/페이지 25행, 분할 행의 비교 한계를 표시했다.
- **운영 장애와 코드 결함 구별**: 라이브·로컬 콘솔에서 반복된 `proxy-primary: warn → error`가 관찰됐다. 단일 브라우저/시점의 실패이며 공급자 상태, 네트워크, 응답 코드, 복구 경로의 전체 장애율은 측정하지 않았다. QQQ·RRG·차트의 결측 상태를 이 오류 하나의 원인으로 귀속하지 않는다.
- **미검증**: AI 키 인증·모델 응답(개인 키/질문 전송 필요), 개인 포트폴리오 저장/복원·삭제·원장 거래 입력, 스크리너 실행 기록 저장과 장기 보관, 모든 화면 크기와 키보드/보조기술, 모든 섹션별 뉴스/SEC/FRED 공식 원문 대사, 모든 프리셋/필터 조합과 모든 873개 종목. 이 항목들은 기능 인증 완료가 아니다.
- **새 로컬 원장 경계**: v56.22에서 `계좌 원장 (TWR/MWR 계산 입력)` UI와 현금흐름 시점·포함 범위·거래/평가액 입력을 확인했다. [index.html](../../index.html)·[aio-workspace.js](../../js/aio-workspace.js)·[portfolio-ledger.js](../../src/data/portfolio-ledger.js)·[risk.js](../../src/domain/portfolio/risk.js)를 가로지른다. 금액 필드의 통화 단위와 첫 평가일 현금흐름 처리의 TWR/MWR 차이는 별도 경계 사례로 검증한다. 입력·영속 저장·수익률 수치의 브라우저 검증은 하지 않았다.
- **추가 구조 후보**: Principles의 내장 개념 지도와 생성 원고가 ID·제목·검토일을 일치시키는지, Masters 분기 이력 shard가 선택 기관 ID와 맞는지, Atlas의 항목별 `invalidation`이 학습 화면까지 전달되는지 대사한다. 포트폴리오 스트레스·집중도는 현금을 제외한 증권 부분 분모임을 선명하게 표시한다. 테마 온도에서 일간 수익률만으로 자금 유입·매수세를 단정하지 않도록 근거 범위를 낮춘다. Breadth fallback의 `server-artifact` 고정 lineage와 마지막 6개 유효 행 간격을 실제 자료 날짜와 대조한다. SEC Frames 동률·5,000건 상한 순위, backtest VaR 인증과 무조건 경고 문구의 공존도 조건부 인수 항목이다.

## 5. 구조 개편 인수 순서

1. **입력 정본과 소비자 수렴**: 기술 분석 symbol/session/close/basis/hash와 실제 차트 렌더(LC-01·16), 포트폴리오 통화·FX·valuationId(LC-08), screener rank 상태(LC-12)를 단일 read model에서 전파한다. 이미 있는 구현에 같은 의미의 독립 writer를 덧붙이지 말고 중복 경로를 제거·통합한다.
2. **근거·시각 결속**: 거시 FRED/live/snapshot(LC-09), FX/채권 carry(LC-14), 브리핑 뉴스/quote 컷(LC-15), 테마 RRG 역사 입력(LC-06), ETF/바스켓 비교와 breadth 분모(LC-10~11), 뉴스의 source/cut/fallback(LC-07)을 소비자 앞단에서 정규화한다.
3. **상태와 문구 정규화**: LC-02의 삼중 상태, LC-05의 출처 검증 상태, Guide의 실제 앵커 연결, SEC Frames의 비교 모집단을 화면·접근성 이름·툴팁에서 동일하게 만든다.
4. **배포 인수**: 로컬 PASS를 라이브 PASS로 자동 승격하지 않는다. 현재 배포 v56.15와 후속 배포본에서 동일 20개 등록 라우트, 핵심 상호작용, 비동기 최종 상태, 외부 원천 경계, 저장/복원 격리 시나리오를 각각 기록한다. 배포는 별도 명시 요청이 있을 때만 수행한다.

## 6. 닫기 기준

- LC-01~05 및 LC-07~16은 재현 입력, 기대, 실제, 수정 후 비교 컷, 브라우저 결과를 각 항목에 추가해야 닫는다. LC-06은 먼저 RRG 계보를 수집해 결함/정상/설계 공백 중 하나로 재분류한다. 코드만 확인한 LC-05·08·10·11·14·16과 조건부 LC-09는 실제 브라우저 acceptance가 남는다.
- 새 구조가 기존 static·headless 게이트를 통과해도 위 브라우저·라이브 인수가 없으면 `미검증`으로 남긴다. 현재 로컬 v56.23의 원장까지 포함한 의미 검수는 별도 항목으로 남긴다.
- 이번 문서는 감사·설계 자료다. 제품 코드 수정, 자동 commit/push/deploy는 수행하지 않았다.
