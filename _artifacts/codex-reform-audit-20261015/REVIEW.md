## 1. 종합 의견

최근 개편은 효과가 있다. 점수·등급을 줄이고, 미국 종가와 한국장·장중 시세를 구분하며, 근거와 반증을 보여주는 방향이 분명해졌다. 종목의 세 탭이 같은 회사를 따라가고, 테마의 상대강도·절대 하락·거시 노출을 구분하며, 스크리너가 과거 우월성을 확인하지 못했다는 사실을 숨기지 않는 점은 유지할 가치가 크다. Worker 예산 정산과 CI SHA를 연결한 배포도 이전보다 엄격하다.

하지만 **모든 검사가 초록이라는 것과 사용자가 올바르게 이해한다는 것 사이에 간격이 크다.** 마지막 대화 삭제와 첫날 입금 계산은 정상 게이트를 통과하면서 틀린 결과를 낸다. 해설은 어느 입력이 판정을 만들었는지 끝까지 전달받지 못해 ‘속도 부담’을 ‘수준 부담’으로 바꾼다. 여러 이름·문구를 개선한 뒤 검증 스킬이 실제 화면을 따라오지 못했다. 표본 독립성처럼 금융적 의미를 검증해야 할 곳에 문자열 존재 검사가 남아 있다.

제 판단으로 다음 개편의 중심은 새로운 기능이나 전면 재작성보다 **같은 사실을 화면·AI·통계·운영 상태가 같은 의미로 말하게 만드는 일**이다. 가족·지인 5명이 쓰는 앱에 175개 열린 QA와 방대한 원장 자체가 사용자 가치를 보장하지 않는다. 자주 쓰는 하루 흐름의 정확성과 복구를 먼저 닫고, 이전한 legacy는 실제로 지워 초기 실행 비용과 다음 수정의 판단 부담을 줄이는 편이 낫다.

아래 F01~F30은 30개 독립적인 확정 버그라는 집계가 아니다. **실행 재현, 라이브 관찰, 정적 계약 충돌, 기존 부채, 설계 의견, 미검증 경계**를 함께 인계한 목록이다. 심각도는 다음 작업의 우선순위다. 앱 exploit이나 실제 금전 손실을 확인하지 않은 항목은 그렇게 쓰지 않았다.

## 3. 즉시 수정할 신뢰·계산 문제

### F01 · P1 · 알려진 취약 DOMPurify 의존성

**정적 확인 + 공식 advisory.** `index.html:45,6742`는 DOMPurify 3.0.9를 preload/CDN/SRI로 고정한다. `js/aio-core.js:138`의 safeHtml은 외부 뉴스·AI·메모 HTML의 보안 경계다. [Cure53 공식 nesting mXSS advisory](https://github.com/cure53/DOMPurify/security/advisories/GHSA-gx9m-whjm-85jf)의 3.x `<3.1.3` 영향 범위에 현재 버전이 포함된다. SRI는 파일 변조 방어이며 그 파일 안의 알려진 결함을 고치지 않는다.

현재 허용 태그·전처리 때문에 **이 앱에서 XSS 성공을 입증한 것은 아니다.** 지원되는 보안 수정 버전으로 업데이트하고 preload·script·SRI를 같이 바꾼다. 패키지 밖 CDN 자산도 취약점 목록에 넣는다. 완료 기준은 실제 배포 URL 확인, 뉴스·AI 정상 HTML 회귀와 악성 HTML 비실행의 브라우저 검증이다.
