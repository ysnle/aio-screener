# 시장·AI 내러티브를 기존 시스템에 연결하는 설계

2026-11-05 · **현행 코드의 정적 조사 + 제안. 구현·운영 실측 전.** 사용자 질문의 ‘AI 내러티브’는 AI 산업을 둘러싼 수요·투자·수익화·자금조달 이야기이며, 이 문서에서는 그 해석을 생성하는 모델과 구분한다. X 자료는 [10월 이후 종합](OCTOBER-SYNTHESIS-HANDOFF.md), 직접 읽은 범위는 [색인](README.md)을 따른다. 전수 독해로 가정하지 않는다.

## 먼저 결정할 구조

**하나의 사건·사실 원장과 하나의 공통 해석을 유지하고, 여러 화면이 같은 사실을 질문에 맞게 읽는다.** 이야기를 새 고정 테마 목록으로 복사해 추가하지 않는다. 기존 `market-day`의 사실·관계와 `scenario-state`의 조건을 우선 재사용한다. 그 위에 출처를 가진 **주장과 반론, 변화 이력, 다음에 확인할 사건**을 얇게 연결하는 것이 제안이다. 같은 내용이 오늘·시장 상태·테마·종목·스크리너·AI 패널에서 다르게 판단되는 일을 줄인다.

순서: ① 외부에서 실제로 관측한 사실 → ② 누가 어떤 해석을 내놓았는지 → ③ 그 해석을 지지·반박할 수 있는 구체적 관측 → ④ 새 사실이 전후 판단을 어떻게 바꿨는지 → ⑤ 다가올 확인 시점. ‘미확인’, ‘자료 없음’, ‘상충’, ‘기존 결론 유지’도 유효한 결과다. 이야기는 사실의 묶음이 아니라 **반증 가능한 여러 설명의 묶음**이며, 주가 움직임과 함께 등장했다는 이유로 인과를 확정하지 않는다.

## 현재 코드에서 확인한 기반과 한계

| `src/domain/interpretation/market-interpretation.js`, `public-data/scenario-state.json`, `src/domain/scenarios/theme-stage.js` | 시장·테마와 여러 화면이 공통 조건/단계를 사용하도록 설계되어 있다. | 시장·산업 해석과 사용자에게 제시되는 조건이 달라지지 않도록 이 경로를 먼저 확장 검토한다. 실제 각 화면의 최신 동작은 브라우저 재검증이 필요하다. |
| `src/ai/analysis/evidence-inputs.js`, `src/ai/context-builder.js` | AI 입력에서 ID 충돌, 잘못된 출처·시각·단위 등을 거르고 참고용 정책을 보존하는 경로가 있다. | 기존 근거 정책을 우회해 2차 소식·의견을 확정 지표로 모델에 넣지 않는다. |

`marketAnalysis`는 `src/data/server-market-analysis.js`의 별도 소비 게이트를 지나며, 브리핑에는 `data.json.marketTimeline`의 시간대별 슬롯도 있다. 브리핑의 하루 사건 묶음과 시장 해석을 중복 생성하기보다 같은 사건에 대한 서로 다른 표현으로 연결한다. 이 표는 정적 조사이며 현재 배포의 동작·지연 보장은 확인하지 않았다.

## 제안: 최소한의 의미 계층

아래는 **기존 파일이나 계약이 현재 이 필드를 모두 갖고 있다는 뜻이 아니다.** 1단계에서는 기존 행에 관계 ID를 붙여 검증하고, 빠진 속성이 실제 요구될 때만 버전이 있는 공통 뷰 또는 소형 sidecar를 도입한다. `market-day` 전체 복제나 두 번째 사실 원장은 만들지 않는다.

| 개체 | 필요한 필드 | 원칙 |
|---|---|---|
| 사건 `event` | 안정 ID, 대상·주제, 사건 종류, 발생일, 발표/공개 시각, 관측·수집 시각, 원문 ID, 정정 관계 | 예정·발표·수정은 별개 사건이며 같은 발표의 복수 기사와 중복 구별. 시간대·거래세션을 보존한다. |
| 관측 `observation` | 기존 evidence ID, 값·단위·기간·기준일, 원천·판본, 누락·이월·갱신 기한 | 8월 매출이 10월에 발표됐다면 8월에는 알 수 없었다. 리서치 채널의 숫자는 원천 대조 전 수치 근거가 아니다. |
| 주장 `claim` | 주장 ID·원문/작성자, 대상·방향·기간, claim 유형(발표 사실/전망/의견/추론), 근거 ID와 공개 시점 | ‘전문가가 말했다’와 ‘그대로 실현됐다’를 분리한다. 상대방의 이해관계와 인용 관계를 표시할 수 있게 한다. |
| 관계 `link` | `supports`, `challenges`, `alternative`, `supersedes`, `related` 등과 근거 ID, 연결 주체·근거 설명 | 한 사건이 여러 가설과 관련되어도 인과 링크를 자동 확정하지 않는다. 반대 자료가 없는 것과 반대가 없는 것은 다르다. |
| 이야기 `story` | 안정 ID, 독립 주장들의 묶음, 시간 범위, 관련 이벤트·대상·기존 화면, 마지막 검토 시각, 요약 revision | 둘 이상의 상충 가설을 담을 수 있다. 언급 급증은 ‘많이 언급됨’으로만 취급하고 진실성·예측력으로 승격하지 않는다. |
| 변경 `revision` | 이전/새 상태, 변경 사건 ID, 무엇이 왜 바뀌었는지, 사용 가능 시각, 이전 표현의 유효 범위 | 바뀌지 않은 결론도 기록 가능. 데이터 정정은 과거 원문을 지우지 않고 supersedes로 이어 붙인다. |

원문 링크에는 공개 가능 여부·접근 시각·출처 유형을 둔다. 개인 북마크나 비공개 계정·사용자 메모는 공개 GitHub Pages에 자동 복제하지 않는다. 외부 콘텐츠는 링크와 필요한 범위의 짧은 요약을 우선하고 원문 대량 재배포·유료 장벽 우회를 하지 않는다. 수집 가능성과 이용 조건을 먼저 확인한다.

## 갱신과 변경 감지

1. **기존 주기:** Actions가 성공적으로 발행한 입력을 읽어 사건과 관측을 정규화한다. 이벤트의 발생일, 공개 시각, 수집 시각, 제품 발행 시각을 따로 둔다. API나 뉴스가 늦게 도착할 수 있으므로 ‘몇 분마다 확인 예정’과 ‘마지막으로 확인된 시각’을 구분한다.
2. **중복 통합:** 원문 URL·공식 발표 ID·대상·기간으로 동일 발표를 묶고 기사들은 출처로 남긴다. 제목이 비슷하다는 이유만으로 별도 사건을 병합하지 않는다. 판단이 불명확하면 자동 병합을 보류한다. 텔레그램이 같은 기사를 여러 번 중계해도 독립 근거 여러 건으로 세지 않는다.
3. **중요 변화 후보:** 새 공식 발표·실적, 기존 주장 정정, 기존 근거의 만료, 사용 중인 관측값의 의미 있는 변화, 사용자에게 영향을 주는 일정 변경, 기존 상위 이야기의 실질 변경을 감지한다. 임계값은 대상의 변동성과 데이터 주기를 고려한 **운영용 후보 선별**이며 가격 예측이나 매매 알림 규칙이 아니다. 이벤트 유형별 재생성 조건을 조정하기 전에 실제 기존 입력과 표본을 측정한다.
4. **작은 변경은 결정론적으로 갱신:** 시각·정정·원문 링크·관측값은 모델 없이 고친다. 같은 사건을 다룬 번역·재게시 또는 변하지 않은 서명으로 무한 생성하지 않는다. 현재 `blockedAttemptKey`의 반복 차단과 변경 전후 입력 서명을 보존한다.
5. **의미 있는 변화만 설명 생성:** 공표 이후 이용 가능한 관측과 서로 다른 주장의 근거를 묶어 공통 해석을 갱신한다. 입력이 불충분하면 ‘지금 확인할 수 없음’을 반환한다. 모델은 신규 사실·인과·수치를 만들어 내지 않고 입력에 연결된 문장만 만들며, 실패하면 관측과 출처를 그대로 보여준다.
6. **이력과 반증:** 수정·철회·발표 지연, 기존 가설의 지지·약화와 대체 가설을 기록한다. 시간별 스냅샷은 공개 당시 이용 가능했던 근거만 참조한다. 정정 후에도 과거 화면에서 무엇이 알려져 있었는지 재현 가능해야 한다. 이력의 보유 기간·크기는 현재 아티팩트 예산을 측정한 뒤 정한다.

미국의 최신 정규장 완료 종가를 기준으로 하는 시장 상태와, 장중·장외 속보는 별도 시각과 범위를 표기한다. 거시 월간 발표는 다음 예정 발표에 맞추고 13F 등 느린 데이터는 해당 공시 주기·기한으로 판단한다. 오래된 자료를 갱신 시각만 바꾸어 최신으로 포장하지 않는다.

## 예시: 반도체와 AI 인프라

사건 A는 공식 반도체 매출 발표, 사건 B는 특정 기업의 실적 또는 투자 계획, 사건 C는 ETF 가격 변화라고 하자. A는 **산업 매출 관측**, B는 **해당 기업의 발표·계획**, C는 **시장 가격 관측**이다. 세 사건이 같은 이야기에 속해도 아래 가설을 별도로 둔다.

- **가설 1:** 높은 매출 성장과 설비투자 계획은 공급망 수요를 지지한다. 확인할 것: 실제 인도와 주문, 현금흐름, 다음 공시.
- **가설 2:** 높은 성장에도 기저효과·기대치·자본비용 변화로 이익 전망이나 밸류에이션이 조정될 수 있다. 확인할 것: 동일 시점의 기대치, 이익 전망, 금리·신용.
- **가설 3:** 가격 하락에 수급 청산이 기여했을 수 있다. 확인할 것: 출처가 있는 포지션·거래자료. 가격 하락만으로 매도자의 의도는 확인 불가.

예정된 발표가 나오면 ‘기존 가설 A가 사실’이라고 자동 전환하지 않는다. 발표의 실제 내용·기대치 보유 여부·기준일을 먼저 확인하고 각각의 가설에 대한 지지·반박·미확인을 갱신한다. 기대치의 발표 전 저장본이 없으면 ‘예상 상회/하회’를 만들지 않는다.

## 모델·비용·장애 경계

- 시장 텍스트와 채팅은 기존 공유 Worker와 원자적 월간 장부를 사용한다. `scripts/lib/ai-shared-analysis.mjs`의 현재 모델과 목적별 요청 경로를 재사용하고, 개인 키·별도 비용 계정으로 우회하지 않는다. $20은 경고하는 공유 목표이며 자동 차단 한도로 바꾸지 않는다. 실제 검색 허용과 호출 수는 Worker 계약을 따른다.
- 새 이야기마다 정기적 모델 호출을 예약하지 않는다. 중복 묶기·서명 비교·후보 선별과 캐시를 먼저 수행하며, 기존 생성의 재시도와 동일 입력 실패 억제를 존중한다. 호출·토큰·검색 비용과 누락·오류 수를 목적별로 기존 영수증에서 확인한다. 예측 없는 목표 예산·실측 뒤 갱신 빈도를 조정한다.
- 루머·보도·사실·추론은 입력과 출력에 같은 등급을 유지하고 출처 귀속을 한다. 검색 결과는 차트·점수의 숫자 입력이 아니며 인용 링크가 신선함을 보증하지 않는다. 외부 본문 속 모델 명령·URL은 데이터로만 처리하고 실행하지 않는다. 확인되지 않은 종목명은 정확한 종목 레지스트리 일치 없이는 연결하지 않는다.
- 생성 실패 또는 입력 모순 때는 확인된 관측과 해당 출처를 표시하고 해석을 ‘없음’으로 둔다. 이전에 검증된 텍스트를 유지할 때는 원래 생성 시각·대상 근거·보존 이유를 보여주고 현행 데이터와 재검증한다. 수집 실패, 공개되지 않음, 시차상 아직 발표 전, 오래된 값은 구분한다.
- 내부 의미 검증은 수치·날짜·출처·사실 관계의 불일치, 인과의 무근거 단정, 반증 누락, 과거 시점 누출을 찾는 방어 장치다. 자동 검증 통과를 ‘분석의 정확성 검증 완료’로 표시하지 않는다. 성공확률·등급·개인별 매매 지시를 생성하지 않는다.

## 구현 배치와 수용 시험

1. **현행 계보 실측:** `market-day`의 사건·출처 ID, `marketAnalysis`의 입력 ID·서명·생성 시각, `scenario-state`·AI 패널의 연결을 같은 실제 스냅샷에서 조사한다. 누락이나 서로 다른 기준일은 목록화하고 기존 코드와 현재 브라우저 표시를 대조한다. 완료 조건: 사용자가 보는 한 문장에서 해당 관측 원천까지 따라갈 수 있고, 불가능한 것은 미확인으로 남는다.
2. **의미 관계의 작은 시험:** 반도체 및 AI 자금조달의 제한된 사례로 사실↔주장↔반론↔다음 이벤트를 기존 ID 위에 연결한다. 검색·원천 확보 범위가 작으면 ‘자료 부족’을 유지하고 표본을 시장 전체로 일반화하지 않는다. 완료 조건: 동일 출처를 여러 화면이 일관되게 읽고 사건 수정 시 이전 설명이 남는다.
3. **내러티브 변경 비교:** 기존 refresh 이후 사건·서명 변화를 검사하고 필요한 경우만 설명을 다시 쓴다. 최초에는 기존 전체 해석과 병행 비교하며, 검증 전 새 출력이 기존 결과를 덮지 않는다. 완료 조건: 같은 입력·같은 KST 08시 기준 문장일·유효한 캐시 안에서 불필요한 중복 호출을 피하고, 의미 있는 정정·반론의 추가는 재평가한다. 문장일 변경, 캐시 만료와 실패 재시도는 현행 정책에 따라 재생성이 가능하다. 뉴스 지연과 주말 모드에서 잘못된 실시간 인상을 주지 않는다.
4. **화면과 AI 접합:** 오늘·시장·테마·종목·스크리너·AI 패널이 동일 story/claim/evidence revision을 소비하되 각 화면에서 답할 질문에 맞는 부분만 보여준다. 완료 조건: 링크·대상·시점이 화면 이동 후 유지되고 키보드·터치와 작은 화면에서 출처·반론을 열 수 있다.
5. **운영 전 검증:** Actions fixture로 지연·실패·정정·동시 입력·이전 아티팩트 복구를 재현하고, 실제 브라우저에서 데이터 누락과 오래됨을 확인한다. 공유 장부·경고·검증 로직과 내러티브 lifecycle을 수정하면 해당 위험 기반 QA 및 모델 검사 게이트를 적용한다. 외부 생산자는 GitHub Actions에서만 실행한다.

대표 시험: ① 같은 기사를 두 채널이 전해도 독립 근거 하나 ② 발표일 전 시뮬레이션에서 사후 통계를 사용하지 않음 ③ 잠정 속보가 정정되면 이전 표현을 숨기지 않고 정정 연결 ④ 서로 반대 의견을 합쳐 합의로 만들지 않음 ⑤ 값 하나가 누락되면 0이나 최신으로 대체하지 않음 ⑥ 장중 값과 직전 미국장 종가를 같은 시각으로 표현하지 않음 ⑦ 사용자 요청이나 X 원문에 삽입된 명령이 데이터 정책을 바꾸지 않음 ⑧ 모델 실패 시 근거 기반 상태는 유지하고 추론은 비워 둠 ⑨ 동일 입력·문장일·유효 캐시 조건에서 불필요한 유료 호출을 반복하지 않으며 정책상 재생성은 허용함 ⑩ 화면·AI 응답이 같은 근거 revision과 날짜를 표시함. 실제 API 지연, 데이터 권리, 비용, 품질 및 예측력은 별도로 검증해야 한다.

정정과 과거 시점 재생을 위한 저장소는 **제안**이다. 현행 `src/domain/market-day/facts.js`는 현재 아티팩트에서 최근 하루의 사실을 만드는 구조로, 모든 사실에 취득·이용 가능 시각, 원천별 정정 ID 및 장기 이력이 이미 있다고 가정할 수 없다. 별도의 `src/domain/screener/evidence-lineage.js`와 실제 필드를 대조한 뒤 스키마 버전 또는 sidecar, 보존 기간, 정정 전 원본과 이용 가능 시점의 재생을 설계·검증한다.
