## 범위와 근거의 경계

- 여기의 ‘10월 이후’는 **기존 10/16~11/02 연구 기록과 그 무렵 게시된 자료를 바탕으로 한 작업 범위**다. 게시일·원장 작성일은 북마크 저장일이 아니다. X 화면에서 저장일과 전체 목록의 완전성을 확인하지 못했으므로 10월 이후 저장분을 전부 읽거나 반영했다고 주장할 수 없다. 11/05에 관찰한 URL 473개는 인용 등을 포함하는 부분 목록이지 북마크 건수가 아니다.
- 아래의 X 출처별 해석은 표시가 없는 한 **과거 연구 패킷의 정리**를 재검토한 것이다. 이 문서 작성자가 댓글, 인용, 영상 및 이미지를 다시 직접 열람했다는 뜻이 아니다. 현재 직접 열람한 자료와 못 읽은 부분은 위 색인의 각 원장에 따로 적는다. 과거 패킷의 검증 등급 역시 당시의 판단이며 독립적인 원천 대조를 대체하지 않는다.
- 10/16 당시 원장은 834건(투자 분석 732건, 비투자 102건)과 수집 오류 4건을 기록했다. 이후 원장에 기재된 신규 추정치와 선별된 패킷의 출처 수는 서로 다른 집합으로 중복될 수 있어 합산하지 않는다. 11/01 비투자 자료 일부의 댓글·인용과 본문, 11/02의 영상 1건과 잘린 게시물은 당시 기록상 미열람이다.
- 가격 현상과 주장에 대한 원인 해석을 구분한다. 특정 하락이 ‘처음 10월에 시작했다’고 일반화하지 않는다. SOXX는 6월 고점 이후 7월에도 하락했다는 [당시 보도](https://www.axios.com/2026/07/19/ai-chips-stocks-china)가 있다. 지수와 ETF의 구성·기준시각·고점은 다를 수 있다. 로컬 `public-data/history.json`에서 SMH는 9월에도 하락 구간이 있었고 10/05~10/16에도 큰 폭으로 하락했다. 다만 관측 시각의 의미 및 외부 원천 검증 전에는 이 원장 값의 기준을 확정하지 않는다. 11/03 행의 SMH는 11/02 값 이월이므로 `fieldMeta.smh.sessionDate`를 확인한다. 과거 화면 간 수익률 불일치 사례 P2170도 재현 후보로 남긴다.

## 화면 구조: 같은 질문을 따라 이동

### 1. 오늘 → 시장 상태: ‘무슨 일이 있었나’와 ‘무엇을 뜻할 수 있나’

첫 화면은 중요 사건과 기준 시각을 먼저 보여 주고, 시장 상태에서는 같은 기준일의 지수 추세와 참여도, 이익 전망, 신용을 한 흐름으로 연결한다. 각 항목은 **관측 / 해석 후보 / 반대 관측 / 다음 확인 시점**을 갖는다. 이벤트 전 기대치가 없으면 비워 두고 발표 후 결과를 과거 기대치로 역삽입하지 않는다. 참여도는 기존 시장 상태 섹션의 증거로 넣으며 독립 점수를 더하지 않는다.

```text
시장 한 줄 결론                        직전 미국 정규장 종가 · 날짜
[지수 추세와 참여도: 시간축·값축·동일 유니버스]
관측: 업종별 상대 변화  |  설명 A: 주도권 이동  |  설명 B: 위험 회피
각 설명에 부합/반대하는 관측과 아직 없는 데이터
다음 공식 이벤트 → 조건별 전파 경로와 확인할 것
```

`src/domain/market/page-flow.js`, `src/domain/market/regime-scenarios.js`, `src/ui/components/market-regime.js`, `src/domain/market-day/facts.js`를 확장 후보로 검토한다. 현재 정적 코드 관찰만으로 실제 화면에서 내용이 보이거나 동일하게 동작한다고 판단하지 않는다.

### 2. 매크로 → 테마: ‘자금과 비용이 어디로 전해지나’

금리·신용·달러·유가의 **변화 자체**와 공급망에 미치는 가능한 효과를 구분한다. HY/IG 등급별 스프레드를 같은 관측일과 기간으로 비교하고, 사모신용 자료가 없으면 공개시장 스프레드로 대체했다고 명시한다. 기존 국채 입찰 원장 `public-data/treasury-auctions.json`과 `src/domain/macro/treasury-auctions.js`를 우선 확인한다.

테마 상세는 `수요·주문 → 자금·전력 → 공급 병목 → 인도 → 매출·마진·현금흐름`을 단계형으로 표현한다. 데이터센터는 발표·건설·전력 연결·가동을 구분하고 각 단계의 출처·날짜를 별도로 붙인다. 병목의 공급자/증설 수혜/가동률 수혜는 서로 다른 역할과 시차를 갖는 가설이며, 이름만 AI에 속한다고 매출 기여를 추정하지 않는다. `src/domain/themes/ai-capex-flow.js`, `src/ui/pages/themes.js`의 현재 구조와 자료 가용성을 먼저 검토한다.

### 3. 테마 → 종목 → 스크리너: ‘누가, 어떤 조건에서 다른가’

종목에서 **발표 전 기대 / 실제 / 다음 전망 / 발표 이후 가격 반응**을 각각 구분한다. 동일 기간·통화·회계 기준이 맞을 때만 차이를 계산하며 기대 자료가 없거나 발표 후에야 수집되었다면 비교를 보류한다. 매출 수준과 성장률 및 성장률 변화, 재고·매출채권·현금흐름은 가능한 경우 별개의 기간 축으로 제시한다.

스크리너는 기존 조건과 열을 먼저 정리해 조건별 충족·미충족·미확인을 한 행에서 설명한다. **전체 대상 수 / 각 조건 계산 가능 수 / 필터 통과 수 / 현재 보이는 수**를 섞지 않는다. 예컨대 반도체 후보의 가격과 실적 추세를 같은 기준일에 볼 수 있어도 ‘추천’은 아니다. `src/ui/pages/entity.js`, `src/ui/pages/screener.js`, `src/domain/screener/evidence-lineage.js`의 재사용 범위를 확인한다.

각 화면은 직접 진입해도 첫 결론과 날짜가 보여야 한다. 모바일에서는 주요 열과 행 상세를 우선하고, 용어·기간·출처는 키보드와 터치로 볼 수 있어야 한다. 차트의 축과 기간을 유지하며 로딩·지연·부분 누락·수집 실패·결과 없음은 구별한다.

## 우선순위와 완료 조건

1. **근거와 기준 정리:** 기존 원장·현재 화면의 사실 ID와 기준일을 대조하고, 이월값·기대치 미확보·원문 미검증을 드러낸다. 같은 수치가 화면마다 다르면 원인부터 추적한다. 완료 조건: 대표 사례에서 원천과 계산·기준일을 사용자와 검증자가 따라갈 수 있다.
2. **핵심 동선 개편:** 시장 상태 → 테마 → 종목 → 스크리너의 질문·차트·반론·상세 순서를 기존 컴포넌트 위에서 재배치한다. 완료 조건: 직접 진입과 앞뒤 이동에서 대상과 시점이 유지되고 충족/누락이 섞이지 않는다.
3. **공급망·실적 심화:** 공식 공시로 확인되는 연결과 가능한 시계열만 단계적으로 추가한다. 완료 조건: 공급·수요·자금·수익의 다른 개념을 별개로 표시하고, 각 단계에 근거 또는 명확한 빈 상태가 있다.
4. **검증과 후속 읽기:** 현재 main의 데스크톱·태블릿·모바일에서 탐색, 표, 차트, 빈 상태, 키보드 및 화면 읽기를 실제 확인한다. 데이터 계약은 기준일·수정·결측·동일 분모·시점 누수 사례를 시험한다. X에서는 미열람 본문·인용·댓글·이미지·영상·외부 보고서를 항목별로 이어서 확인하되 접근 불가와 저장일 불명을 그대로 기록한다.

수용 테스트는 ‘설명과 실제 값이 같은 출처를 가리키는가’, ‘반대 근거와 불확실성이 살아 있는가’, ‘예측이나 거래 지시처럼 보이지 않는가’를 포함한다. 이 문서는 설계이며 코드 변경, 실제 화면 검증, 전체 북마크 완독을 의미하지 않는다.
