# 북마크 기반 화면 구조 재설계 핸드오프

작성: 2026-11-05 · 상태: **제안 / 부분 자료 조사 / 구현 전**

시장·AI 이야기가 시간에 따라 달라지는 화면 동선은 [내러티브 화면 기획](NARRATIVE-UX-HANDOFF.md), 기존 생산·근거 시스템과의 결합 및 정정·갱신은 [시스템 통합안](NARRATIVE-SYSTEM-HANDOFF.md)을 함께 따른다.

## 결정과 범위

기존 아홉 사용자 화면을 유지하면서 각 화면의 질문과 정보의 순서를 다시 묶는다. 핵심 이동은 **오늘 무슨 일이 있었나 → 현재 시장의 조건과 반대 근거는 무엇인가 → 어떤 산업으로 전파되는가 → 이 기업은 무엇이 다른가 → 어떤 조건으로 후보를 살펴볼까**다. 사용자가 어떤 화면으로 직접 들어오더라도 그 화면의 첫 결론과 기준일을 볼 수 있게 하고, 상세 이동은 선택 사항으로 둔다. 스크리너 순위나 조건 충족 수를 추천·예측으로 바꾸지 않는다.

이 제안은 이번에 직접 읽은 일부 X 원문과 `design-draft.md`, `READING-NOTES.md`, `ADDITIONAL-SOURCES.md`, `PROCESS-SOURCES.md`, `CONTINUED-A.md`~`CONTINUED-E.md`, `RAOUL-PAL-CHART-REVIEW.md`의 기록을 바탕으로 한다. 전체 북마크 분석이 아니며 각 출처의 검증·미열람 범위는 해당 원장이 우선한다. 현재 코드 관찰은 정적 조사다. 화면의 현재 동작과 밀도, 제안의 사용성은 같은 버전의 실제 브라우저에서 검증해야 한다.

## 화면별 역할과 재배치

| 사용자 화면 | 첫 질문 | 첫 화면과 순서 | 이어지는 곳 |
|---|---|---|---|
| 오늘 | 오늘 무엇이 중요한가 | 가장 중요한 한 줄과 기준 시각 → 지수·핵심 자산의 축 있는 차트 → 중요 사건 2~3개와 왜 중요한지 → 종목·뉴스 | 사건의 시장 상태·관련 테마·종목·원문 |
| 브리핑·뉴스 | 지난 24시간에 무엇이 확인됐나 | 중요도 순 사건 묶음 → 원문과 발표 시각 → 확인된 사실과 해석 → 이미 반영된 기대/아직 모르는 것 | 해당 사건 상세·시장·테마 |
| 시장 상태 | 현재 조건과 다음 분기는 무엇인가 | 한 줄 진단과 기준일 → 지수·참여도 차트 → 핵심 축별 변화 → 서로 충돌하는 근거 → 예정 이벤트별 조건·반증 | 매크로·주도 테마·근거 원문 |
| 매크로 | 금리·물가·달러·원자재가 어떻게 연결되나 | 중요한 변화 한 줄 → 각 자산의 기간·단위가 보이는 추세 → 관측과 가능한 전달 경로 → 대안 원인과 반증 | 시장 상태·영향받는 테마 |
| 기술적 분석 | 가격이 중요한 범위에서 어떻게 반응했나 | 지수/종목 선택과 종가 기준 → 축·기간이 보이는 가격·거래량 → 지지·저항 후보 및 돌파 이후 반응 → 확인 못한 조건 | 종목과 스크리너의 같은 기준 |
| 테마·섹터 | 강세의 범위와 원인이 얼마나 넓은가 | 테마의 변화 결론 → 기준 대비 분포·상대강도 → 원인 가설과 반대 근거 → 구성 종목의 역할·다가올 이벤트 → 접힌 공급망 | 개별 종목과 이벤트 |
| 스크리너 | 어떤 조건의 종목이 있는가 | 질문 선택 → 조건·기준일·계산 가능/누락 분모 → 결과 표 → 행의 충족·미충족·미확인과 원문 → 종목 | 종목과 관련 테마 |
| 종목 | 이 회사의 사업·실적·가격은 무엇을 말하나 | 회사와 현재 쟁점 한 줄 → 종가 차트 → 실적의 사전 기대/실제/다음 전망/반응 → 사업부·현금흐름 → 테마 연관과 반대 조건 | 해당 발표 원문·테마·스크리너 |
| 포트폴리오 | 전체의 노출과 확인할 위험은 무엇인가 | 보유 입력/빈 상태 → 실제 구성·분산·공통 노출과 데이터 기준 → 일반적 선택지의 조건·비용 → 기록한 가설 | 종목·테마·교육 자료 |
| 리서치 라이브러리 | 왜 이런 해석이 가능한가 | 개념 한 줄과 도식 → 사례의 근거·반론·적용 한계 → 참고 자료·관련 화면 | 관련 현재 화면 |

표의 브리핑·뉴스는 ‘오늘’ 영역의 하위 경험이며 새 최상위 라우트를 추가하라는 뜻이 아니다. 한국 자료는 ‘한국’을 표시한 보조 흐름으로 두고 대상·데이터 기준이 미국과 다르면 분리한다. 투자 권유·가격·수량·시점이나 근거 없는 등급은 제공하지 않는다.

## 우선 화면의 구체 구조

### 1. 시장 상태 — 사건과 현재 조건을 분리

```
[시장 상태 한 줄]                         [직전 미국 정규장 종가 · 날짜]
[지수와 참여도 추세: 시간축·값축·주요 이벤트]
현재 조건       개선을 지지하는 관측       반대하거나 아직 없는 관측
[다가올 공식 이벤트] → 조건 A: 확인할 것과 가능한 파급
                    → 조건 B: 확인할 것과 가능한 파급
자세히: 데이터 정의 · 분모 · 출처 · 일자 · 추가 축
```

- Minervini 글의 선거·계절성과 댓글의 이평선 방향 구분, Humble 글의 결과 이후 실제 반응 확인, Anna Wong 글의 금리와 투자 가설 간 긴장을 같은 흐름에 배치한다. 주간 이평선 위 종목 비율, **개별 종목의 이평선이 상승하면서 그 위에 있는 비율**, 해당 비율의 기간별 변화는 서로 다른 값이다. 충분한 점별 이력과 동일 유니버스가 없으면 계산하지 않는다.
- 시장 축과 과거 선거 사례는 독립적으로 중복 점수화하지 않는다. 날짜가 다른 관측치를 같은 순간인 것처럼 한 문장으로 합치지 않는다. 이벤트 전 기대치가 없으면 ‘미제공’, 이벤트 후 관측이 아직 없으면 ‘발표 후 확인’으로 표시한다.
- 현재 `src/domain/market/page-flow.js`, `regime-scenarios.js`, `src/ui/components/market-regime.js`의 구조를 먼저 재사용한다. 새 시장폭 전용 블록을 늘리기보다 기존 축의 근거로 흡수한다.

### 2. 테마·섹터 — 같은 원인이라는 가설을 검증

```
[테마 한 줄: 무엇이 바뀌었나] [가격 기준일 / 분류 검토일]
[상대강도 추세]  [테마 내부 구성종목의 상승·하락 분포]
이유 후보: 사건/실적/거시  │ 반대 근거/다른 설명
관련 기업: 역할 · 최근 실적 이벤트 · 관측 가능한 연결 근거
자세히: 공급망의 연결 범위 · 데이터 정의 · 결측
```

- 성장하는 AI 산업과 기업의 가격·현금흐름·사업 노출은 별도다. `scale-up/out/across`는 개념 설명이며 특정 기업 매출 기여나 우위로 자동 승격하지 않는다. 발표된 근거와 회사의 주장, 작성자의 추론을 분리한다.
- AI 공급망·설비투자 띠를 또 만드는 대신 `src/ui/pages/themes.js`의 기존 상대강도·상세·구성종목·AI 흐름을 질문별로 묶는다. 주가가 함께 움직였다는 사실만으로 같은 원인을 확정하지 않는다.
- 산업의 `수요·발주 → 공급 병목 → 수주잔고·인도 → 실적 → 가격에 반영된 기대`를 각 단계의 근거가 있을 때 연결한다. 예를 들어 조선·방산 보고서의 목차와 발췌는 이 흐름을 설명하는 참고 구조이지만 745쪽 전문은 미열람이다. 성장률의 정점·양의 성장·수준 하락은 별개 항목으로 보여주며 주가 정점의 확정 규칙으로 쓰지 않는다.
- 정적 코드상 상세 테마 가격 기준이 `title`에만 붙는 경로(`themes.js`의 가격 렌더링)가 있어 터치·키보드 이용자가 놓칠 가능성이 있다. 짧은 기준을 값 옆에 보이게 하고 실제 화면에서 확인한다. 분류 검토일과 가격 관측일은 별도로 둔다.

### 3. 종목 — ‘발표 전 → 발표 → 반응’의 네 칸

```
[기업·쟁점 한 줄] [회사별 기준일]
[종가 차트 + 실적 발표 시점]
발표 전 기대 | 발표된 실제 | 다음 전망 | 발표 후 관측된 가격 반응
사업부별 성장·이익 │ 현금흐름·재고·매출채권 │ 미공개/수집 실패
같은 테마의 역할과 반대 조건 → 원문/관련 테마
```

- 실적치와 예상치는 동일 기간·통화·GAAP/조정 정의일 때만 차이를 보여 준다. 사전 추정치의 사용 가능 시각과 수정 이력을 저장하고, 발표 후 숫자를 과거에 넣지 않는다. 실제 수집 실패와 회사의 미공개는 다르다.
- 기업의 고객·공급망 관계는 확인된 문서가 있을 때만 표시한다. ‘AI 관련’과 ‘AI가 매출에 기여한 금액이 공개됨’은 다른 상태다. ETF 파급은 공개 보유비중과 종목 수익률을 같은 시점에 확보했을 때만 단순 기여도로 설명하며 전체 ETF 수익률 예측이 아니다.
- `src/ui/pages/entity.js` 및 기존 실적·컨센서스 읽기를 연결한다. 서로 다른 렌더러에서 서로 다른 기간의 수치를 요약에 합치지 않도록 이벤트·증거 ID를 공유한다.
- 실제 북마크 자료에서 본문과 개별 차트가 서로 다른 EPS 성장률을 표기하거나 양수·적자의 기준이 달라 보이는 사례가 있었다(`CONTINUED-C.md`). 해당 수치의 정오를 단정하지 않되, 서로 다른 측정 기준이 해명되지 않으면 요약을 보류하고 각 출처와 차이를 표시하는 검증 사례로 쓴다.

### 4. 스크리너 — 조건과 분모를 먼저 설명

```
무엇을 찾나요? [추세] [실적 개선] [안정성] [직접 조건]
대상 시장 · 기준일 · 선택한 조건 · 계산 가능 N / 전체 M · 누락
[결과 표: 핵심 열만] [열 선택·정렬·필터]
행 펼침: 충족 / 미충족 / 미확인 + 각 값과 시각 + 반대 조건
→ 종목 보기    → 관련 테마 보기    → 조건 정의 보기
```

- 기존 `src/ui/pages/screener.js`는 이미 여러 열과 조건 상태, 근거 상세를 갖고 있다. 새 랭킹을 만들기보다 용어·집합 관계를 한곳에 정리한다. 순위 산출 대상, 필터 통과, 실제 보이는 행, 단일 조건 계산 대상의 분모가 다르면 각각 명시한다.
- 정렬은 선호하는 정렬일 뿐 매수 추천이 아니다. 수익률·재무·테마·뉴스의 다른 관측 주기와 결측을 합쳐 하나의 확정적 판단으로 바꾸지 않는다. 모바일은 중요한 열을 먼저 두고 행 상세와 가로 스크롤의 존재를 알린다.

## 공통 데이터·기술 계약

1. **한 사실, 여러 화면:** 이벤트 ID, 기업 ID, 지표 ID, 관측일, 공개·이용 가능 시각, 갱신·수정, 단위·기간, 출처와 결측 사유를 유지한다. `src/domain/market-day/facts.js` 및 `src/domain/screener/evidence-lineage.js`, AI 근거 경로를 대조하고 새 원장을 중복 구축하지 않는다.
2. **시간:** 시장 종가와 장중, 발표 전과 후, 공식 발표와 수집 시각을 구별한다. 재생 화면이나 과거 사례는 당시에 이용 가능했던 값만 쓴다. 서로 다른 기준의 숫자는 근접 배치해도 기준을 각각 표시한다.
3. **주장과 관측:** 게시물·댓글은 참고 의견이다. 출처, 차트 단위·축·기준, 표본, 계산법을 확인한 관측만 정량 시각화에 사용한다. 하나의 차트나 선택된 구간의 높은 상관계수는 원인·예측 성공률을 입증하지 않는다.
4. **상태:** 최신/지연/참고/없음의 카드 상태를 유지하고 상세에서 미발표·미공개·수집 실패·비교 불가를 구분한다. 새로운 원천이 필요하면 무료 공식 원천과 권리·주기·유니버스를 먼저 확인한다. 데이터가 없다고 숫자를 지어내거나 출처를 숨기지 않는다.
5. **접근성:** 차트에는 축·단위·시간·텍스트 요약과 대체 표를 제공하고 색상에만 의존하지 않는다. 접힘은 키보드와 보조기술에 상태를 전달한다. 휴대폰·아이패드에서 동일 데이터와 기능을 유지하고, 테이블 스크롤 및 현재 기준을 눈에 보이게 한다.
6. **상태 전이:** 초기 로딩, 정상, 일부 누락, 지연, 수집 실패, 조건 결과 없음, 재시도 중을 구분한다. AI 입력의 제출 중 중복 방지·성공·실패와 복구 경로, 필드 오류와 포커스, 보조기술 알림을 설계에 포함한다. 간결함을 위해 기준일·단위·오류 이유·접근성 이름을 삭제하지 않는다(`CONTINUED-B.md`).

## 단계와 수용 기준
