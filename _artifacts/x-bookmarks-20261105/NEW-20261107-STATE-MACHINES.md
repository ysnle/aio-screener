## 핸드오프 반영: 우선순위와 수용 기준

1. **데이터 갱신·직접 진입:** 로드 중 → 최신/부분/지연/실패 → 수동 재시도 상태와 이벤트를 실제 소비 코드에서 먼저 도출한다. 진행 중 요청의 늦은 응답, 버전 변경, 화면 재진입, 실패 후 재시도를 조합한다. 기존 cache `KNOWN`을 의도된 유예로 받아들일지 수정할지 실제 영향·대안 비용을 확인하고, 어떤 응답 기준이 사용자 화면에서 보장되는지 문서화한다.
2. **시장 내러티브와 정정:** 사건 최초 발표 → 정정·반론 수집 → 이전 버전 보존 → 화면과 AI에 반영의 상태·근거 ID·시각을 설계한다. 첫 버전 이전 시점 재생에서 나중 정정이 새어들지 않아야 하며, 현재 한 화면에서 아직 다른 revision을 쓰는 경우를 확인하거나 차이를 명시한다. 기존 producer 모델만으로 다중 화면의 일관성을 주장하지 않는다.
3. **기업 선택·실적:** 기업 A 요청 → 기업 B 선택 → A의 늦은 응답 → B 응답과, 발표 전 기대치의 취득 시점 미확인 → 실적 발표 → 비교 보류 경로를 시험한다. 회사 식별자가 일치하지 않으면 이전 기업 값이 현재 기업의 사실로 표시되지 않아야 하고, 발표 전 시점이 확인되지 않은 추정치를 서프라이즈로 승격하지 않아야 한다. 유무는 검증 전 미확인이다.
4. **결함 판정 방식:** 각 경로의 소유 함수·입력·도달 가능한 최소 이벤트 순서·기대한 불변조건·실제 결과·사용자 영향·관측 수준(정적, 격리 테스트, 브라우저, 배포)을 기록한다. 모델이 출력한 후보나 이론상 가능한 순서만으로 확정 결함으로 분류하지 않는다. 확인된 결함은 재현 후 수정하고, 기존 실패를 검출하는 회귀 사례를 추가한다.
5. **비용과 유지:** 모든 화면을 무조건 한 파일·하나의 거대한 모델에 모으지 않는다. 공유 경계와 영향이 큰 경로부터 기존 테스트를 재사용하고, bounded model의 이벤트·깊이·가짜 네트워크와 불포함 영역을 명시한다. 런타임 변경 없이 이 기획만으로 모델이 추가되거나 테스트를 통과했다고 주장하지 않는다.

이 항목은 투자 판단 근거가 아니라 스크리너의 데이터 정확성·일관성과 신뢰도를 뒷받침하는 **개발·검증 방식**에 반영한다. 실제 제품에 주가 방향이나 추천으로 노출할 내용은 없다.
