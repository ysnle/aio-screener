# 국내 투자자별 수급 — 재도입 설계안 (종료: 무료 공식 원천 없음)

작성: 2026-10-13 (Claude aio-64가 이전 세션 최종 보고를 저장소에 옮김). 상태: **설계만, 구현 없음.**

## 배경

- P1671(v57.47)에서 브라우저가 네이버 수급·캔들을 직접 부르던 KR 수급 코드(약 620줄)를 퇴역시켰다. 화면에 보이지 않으면서 거시 화면 약 14건·차트 화면 약 18건의 외부 요청을 만들었기 때문이다.
- 소유자 질문(2026-10-13): "데이터 수집 어떻게 하게? 잘 할 수 있으면 국내 투자자 수급 분석은 좋긴 하지."

## 원칙 (AGENTS.md와 일치)

- 느린 데이터는 정적화한다. 브라우저가 원천을 직접 부르지 않고, GitHub Actions가 하루 한 번 만든 정적 파일을 읽는다.
- 로컬 프로듀서 금지. 수집 스크립트는 Actions에서만 실행한다.
- 원천 없는 위젯 금지. 원천·관측일이 확인되지 않으면 섹션을 보류 상태로 표시한다.

## 원천 후보

| 후보 | 장점 | 위험 | 판단 |
|---|---|---|---|
| KRX 정보데이터시스템 "투자자별 거래실적" | 공식 원천, 외국인·기관·개인 일별 순매수 | 로그인 요구 전환 여부 미확인, 데이터센터 IP 차단 가능 | **추천** — Actions 시험 실행 1회로 확인 |
| 네이버 금융 투자자 동향 | 접근 쉬움 | 비공식, 이용 조건상 재배포 위험 | 비추천 |

## 제안 순서

1. `refresh-data.yml`에 KRX 시험 수집 단계 1개를 추가하되, 실패해도 기존 갱신을 막지 않게 경고만 남긴다(`fetch-sp500-weights.mjs`와 같은 격리 방식).
2. 시험 실행이 성공하면 `public-data/kr-investor-flows.json`(코스피·코스닥, 투자자 3분류, 최근 60거래일)을 만들고 lineage 정책을 등록한다.
3. 화면: 거시 또는 한국 시장 섹션에 5일·20일 누적 순매수와 지수 흐름을 한 그림에 놓는다. 한 줄 해석 + 접힌 숫자표 + 접힌 데이터 출처.
4. AI 컨텍스트에는 관측일과 함께 주입한다.

## 시험 결과와 결론 (2026-10-13, 소유자 위임 결정)

- KRX 정보데이터시스템 JSON 엔드포인트(`getJsonData.cmd`, 투자자별 거래실적)에 키 없이 요청하면 HTTP 400과 함께 응답 본문 `LOGOUT`가 돌아온다. 이제 로그인 세션을 요구한다.
- 로그인 계정을 Actions 시크릿으로 넣어 자동 로그인하는 방식은 이용 조건과 계정 보안 위험이 있어 택하지 않는다. 비공식 원천(네이버)은 위 표의 이유로 제외한다.
- **결론: 무료·무키·공식 원천이 없으므로 섹션을 만들지 않고 종료한다.** 공식 OpenAPI(KRX Open API 또는 data.go.kr)에서 투자자별 일별 순매수가 키 발급만으로 제공되면, 위 '제안 순서'를 그대로 재개한다. 이때 필요한 것은 소유자의 API 키 발급뿐이다.
